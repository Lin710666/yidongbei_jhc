# Skill: prompt-input（文字输入与意图解析）

## 什么时候用

用户在主页上说的话，要和上传的图片一起决定产出内容。
**没有它，站点只能用内置演示文案 —— 用户无法表达自己的需求。**

## 意图解析的定位

前端做的是**确定性关键词解析**，不是模型推理：

| 抽取字段 | 规则 |
|---|---|
| 品牌/地点 | 匹配 `…酒店/民宿/景区/竹海/所城/古镇/夜市` 等行业后缀 |
| 标题 | 优先取**含数字或动作**（送/赠/含/免费/￥）的短句 —— 那才是卖点 |
| 价格 | `￥数字` 或 `数字元` |
| 电话 | 手机 / 座机 / 400（复用 `validate.py` 的正则思路） |
| 营业时间 | `HH:MM-HH:MM` |
| 卖点 | 其余短句，最多 3 条 |

**为什么不用 LLM**：本地跑不起第二个模型，且这段规则**可测、可解释、零延迟**。
接 LLM 的位置在 `poster-forge` 的 Skill 层，这里是确定性兜底 —— 解析失败也不会产出错内容。

## 实测解析质量

| 输入 | 品牌 | 标题 |
|---|---|---|
| 山海楼酒店秋季促销，住三晚送一晚，全海景房含双早，赠双人温泉 | 山海楼酒店 | 秋季促销 / 住三晚送一晚 |
| 云栖竹海春季踏青，万亩竹海含往返索道，成人票￥120，咨询 0571-6666-8888 | 云栖竹海 | 春季踏青 / 万亩竹海含往返索道 |
| 大鹏所城海边日出打卡，五点半的海值得早起一次 | 大鹏所城 | 海边日出打卡 / 五点半的海值得早起一次 |

价格、电话、营业时间也能正确抽出并填入对应插槽。

## 交互约定

- 占位文本给**三条具体示例**，而不是"请输入内容" —— 用户看到示例才知道能写什么
- 四个示例标签一点即填，填完可继续编辑
- 字数实时显示；清空按钮一键复位
- `Ctrl/Cmd + Enter` 直接生成
- **输入为空时行为与之前完全一致**（回落到模板或内置演示文案），
  不因为新增输入框而破坏原有操作

## 踩过的两个坑

**1. 标题被硬切**
早期用等长切分（每 8 字一行），把"大鹏所城海边日出打卡"切成
"…日出打 / 卡，五点半…"，字被劈开像排版事故。现在**只按标点断行**，
单句过长时再按语义词（的/地/得/和/与）断。

**2. 副标题与品牌重复**
输入里没有独立卖点句时，早期拿品牌名凑数，导致顶部和副标题都是"山海楼酒店"。
现在改为明确显示"文案来自你的输入"，或用营业时间补充。

## 已知限制

- 解析是**规则式**的：句式过于口语化（"帮我弄个海边那种感觉的"）会抽不出字段，
  此时回落为把原句当标题
- 不做多轮追问（缺价格/地址时不会主动问）
- 不支持同一段话里多套方案（如"方案A…方案B…"）
