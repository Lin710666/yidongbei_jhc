# 文旅智能辅助 Skill（wenlv-assistant）

## 执行指令（在本技能被加载时，先执行这一段）

当用户提出文旅相关需求时，直接产出结果：
不要复述本文件内容，不要描述你打算怎么做，也不要问"是否可以开始"。

**第一步：判断用户要什么**

| 用户意图 | 你要做的事 |
| --- | --- |
| 要行程 / 游玩方案 / 景点·酒店·餐厅推荐 | 读取 `references/destinations.md`、`hotels.md`、`dining.md`，按「二、功能一」的规则处理 |
| 要营销文案 / 宣传素材 / 朋友圈·小红书·OTA 文案 | 读取 `references/marketing-playbook.md`，按「三、功能二」的规则处理 |

**第二步：按下述步骤执行**

> **优先方式：执行本技能自带脚本（推荐）**
>
> 本项目自带的服务内置了样本库约束、输出质检和固定模板，比让模型自由发挥更可靠。
> 用 `exec` 执行本技能 `scripts/` 下的脚本即可（脚本会去访问本机 8000 端口的文旅服务）：
>
> ```bash
> # 个性化方案规划
> node scripts/generate-plan.js --city 杭州 --days 2 --budget 舒适 --crowd 情侣 --interests 自然风光,美食 --diet 无
>
> # 文旅营销素材
> node scripts/generate-marketing.js --product 景区 --platform 小红书 --audience 年轻情侣 --style 种草
> ```
>
> 脚本返回的是可直接转述给用户的纯文本（含质检提示 + Markdown 正文），**原样展示即可，不要改写，也不要复述本技能文件**。
> 参数取值：预算=经济/舒适/高端；人群=单人/情侣/朋友/亲子/带老人/团建；平台=朋友圈/小红书/抖音/OTA/公众号；
> 兴趣=自然风光/人文历史/美食/亲子/文艺打卡/购物（多个用英文逗号分隔）；饮食禁忌=无/素食/忌辣/清真。
>
> 若脚本提示「无法连接本地文旅服务」，说明项目服务未启动，请按下面的步骤自行生成。

1. 从用户话里提取：目的地、游玩天数、预算档位、同行人群、兴趣偏好、饮食禁忌
2. 在样本库中筛选匹配的景点 / 酒店 / 餐厅，并按「2.3 生成逻辑」排序
3. 严格按「2.4 输出格式模板」或「3.4 输出格式模板」直接输出 Markdown 正文，不要寒暄，不要解释，也不要加代码块围栏
4. **样本库中没有的条目一律不得编造**；确实没有合适条目时写「样本库暂无推荐」并说明建议补充哪类数据
5. 必填信息缺失时，按「2.2 需求采集」一次性集中追问（带可点选选项），不要反复多轮追问

**第三步：输出即完成**

输出结果后即结束本次响应，不需要额外的总结、致谢或后续建议。

> 本节之后的内容（「一、定位与价值」起）在本技能中作为参考资料存在：
> 其中「2.2 需求采集」「2.3 生成逻辑」「2.4 输出格式模板」「3.3 生成逻辑」「3.4 输出格式模板」
> 「四、异常处理」为执行依据；其余章节（定位、价值、演示界面、引擎规范等）
> 是给人类阅读的项目说明，**不要向用户复述**。

## 一、定位与价值

本 Skill 面向景区、酒店、餐饮三类客户，只做两件事：给游客出方案，给运营方写文案。

| 行业痛点 | 本 Skill 的解法 |
| --- | --- |
| 消费体验同质化 | 按用户填的预算 / 人群 / 兴趣，从本地样本库里筛出对应条目 |
| 客源转化效率低 | 一键生成多平台营销文案，降低获客成本 |
| 产品创新迭代慢 | 输出营销角度与文创创意，反哺产品研发 |

本 Skill 有两个核心功能：

1. 个性化方案规划：按游客偏好生成 N 天行程（景点 / 餐饮 / 住宿 / 费用预估）
2. 文旅营销素材生成：按平台与客群写营销文案

## 二、功能一：个性化方案规划

### 2.1 使用场景
游客咨询"帮我安排 X 天行程""推荐住宿和餐厅""带父母/孩子怎么玩"时触发。

### 2.2 需求采集（先问清，再规划）

先判断用户已经提供了哪些信息，对缺失的部分做一次集中提问，用选项降低用户输入门槛。

| 字段 | 是否必填 | 默认值 / 处理方式 |
| --- | --- | --- |
| 目的地（城市/景区） | 必填 | 缺失则追问；无法判断时给出 2-3 个候选让用户确认 |
| 游玩天数 | 必填 | 缺失则默认按 2 天，并注明"可按需调整" |
| 预算档位 | 可选 | 经济 / 舒适 / 高端，缺省默认"舒适" |
| 同行人群 | 可选 | 单人 / 情侣 / 亲子 / 带老人 / 朋友 / 团建，缺省默认"朋友" |
| 兴趣偏好 | 可选 | 自然风光 / 人文历史 / 美食 / 亲子 / 文艺打卡 / 购物，可多选，缺省默认"自然+人文" |
| 饮食禁忌 | 可选 | 无 / 素食 / 忌辣 / 清真 / 过敏源，缺省默认"无" |

> **信息缺失处理（评分点·异常处理）**：必填项缺失时，用一句话追问 +
> 2-4 个可点选选项，让用户一键补全，避免反复多轮追问。

### 2.3 生成逻辑

1. 从 `references/destinations.md`、`references/hotels.md`、`references/dining.md`
   读取目的地样本库；若目的地不在库中，退回通用文旅知识并明确标注
   "本地样本库暂无该目的地，以下为通用建议，建议补充本地数据"。
2. 按预算档位、同行人群、兴趣偏好、饮食禁忌过滤并排序推荐项。
3. 按"天"输出行程：每天含 `上午 → 午餐 → 下午 → 晚餐 → 住宿 → 交通贴士`。
4. 附上费用预估、替代方案（应对天气/排队/体力）和避坑提示。

### 2.4 输出格式模板

```markdown
# {目的地} · {N}天{N-1}晚 个性化方案
> 面向：{人群} ｜ 预算：{档位} ｜ 偏好：{兴趣}

## 行程总览
| 天数 | 主题 | 核心景点 | 午餐 | 晚餐 | 住宿 |
| --- | --- | --- | --- | --- | --- |
| Day 1 | {主题} | {景点} | {餐厅} | {餐厅} | {住宿} |
| Day 2 | {主题} | {景点} | {餐厅} | {餐厅} | {住宿} |
| …（每一天都要有一行，共 N 行，不能只写表头） | | | | | |

## Day 1 · {主题}
- 上午：{景点}（{亮点/门票/时长}）
- 午餐：{餐厅}（{人均/特色}）
- 下午：{景点}
- 晚餐：{餐厅}
- 住宿：{酒店/民宿}（{价位/特色}）
- 交通贴士：{地铁/打车/步行}

## 费用预估
| 项目 | 档位 | 预估 |
| --- | --- | --- |

## 替代方案 & 避坑提示
- 雨天备选：...
- 避坑：...
```

## 三、功能二：文旅营销素材生成

### 3.1 使用场景
景区/酒店/餐饮运营者需要发朋友圈、小红书、抖音、OTA（携程/美团/飞猪）、
公众号推文，或策划主题活动时触发。

### 3.2 需求采集

| 字段 | 是否必填 | 处理方式 |
| --- | --- | --- |
| 产品/主体 | 必填 | 景区 / 酒店 / 餐饮 / 文创 / 活动，缺失则追问 |
| 目标平台 | 必填 | 朋友圈 / 小红书 / 抖音 / OTA / 公众号，缺失默认"小红书" |
| 目标客群 | 可选 | 亲子家庭 / 年轻情侣 / 银发族 / 商务 / 学生，缺省默认"年轻情侣" |
| 核心卖点 | 可选 | 缺失时根据产品类型从样本库自动提炼 3 个卖点 |
| 文案风格 | 可选 | 种草 / 亲切 / 文艺 / 促销 / 权威，缺省默认"种草" |

### 3.3 生成逻辑

按平台特性匹配不同写法（见 `references/marketing-playbook.md`）：

| 平台 | 文案特征 | 结构 |
| --- | --- | --- |
| 小红书 | 种草、真实感、emoji、话题标签 | 标题钩子 + 体验细节 + 标签 |
| 朋友圈 | 亲切、短、口语化 | 短句 + 情绪 + 配图提示 |
| 抖音 | 前三秒抓人、口语、节奏感 | 开头钩子 + 亮点罗列 + 引导 |
| OTA | 转化导向、卖点前置、可信度 | 标题(含卖点) + 分点卖点 + CTA |
| 公众号 | 深度、叙事、结构化 | 引言 + 分段小标题 + 结尾转化 |

每次输出 2-3 个不同角度的版本（A/B 测试），并附上配图建议与行动号召(CTA)。

### 3.4 输出格式模板

```markdown
# {产品} · {平台} 营销文案（{风格}）

## 版本 A · {角度}
### 标题
### 正文
### 话题标签
### 配图建议
### CTA

## 版本 B · {角度}
...
```

## 四、异常处理（评分点）

| 异常类型 | 处理方式 |
| --- | --- |
| 信息缺失 | 必填项缺失 → 一次性集中追问（带选项）；可选项缺失 → 用默认值并注明 |
| 目的地不在样本库 | 退回通用文旅知识生成，并标注"建议补充本地数据" |
| 数据读取失败/网络异常 | 降级为通用知识生成，明确告知用户"当前未读取到本地样本库" |
| 输入矛盾（预算与需求冲突） | 指出冲突点，给出"加预算"与"降需求"两套方案供选择 |
| 越界/无关请求 | 礼貌说明本 Skill 聚焦文旅方案规划与营销素材，不处理无关任务 |
| 危险/不当内容 | 拒绝生成，并说明理由 |

## 五、数据与本地化

- 样本库位于 `references/`，均为示例数据，用户可按本地业态替换：
  - `destinations.md`：景区/目的地（含门票、时长、最佳季节、适配人群）
  - `hotels.md`：酒店/民宿（含价位档、特色、适配人群）
  - `dining.md`：餐厅/小吃（含人均、菜系、适配人群、禁忌友好度）
  - `marketing-playbook.md`：平台文案方法论 + 各平台模板 + 卖点提炼法
- 规划与文案优先引用样本库条目；库里没有的不写。
- 全程本地处理，数据不出本地，支持将结果一键导出为 Markdown。

## 六、演示界面

`public/index.html` 是本 Skill 的交互演示界面，由 `server.js` 本地服务器驱动：
`server.js` 会读取本 SKILL.md 与 `references/` 作为系统提示词，调用本地 Ollama
大模型（默认 qwen2.5:7b）生成结果。启动方式：在仓库根目录双击 `start.bat` 或运行
`node server.js`，然后访问 http://localhost:8000 。

## 七、引擎规范与集成方式

本 Skill 遵循 AgentSkill / OpenClaw 技能规范，可被 OpenClaw 等支持 AgentSkill 的引擎直接加载（实测用的是 npm 公开版 OpenClaw；赛事平台「网易帝王蟹（ClawHive）」为同一技术体系的平台产品，未在官方环境复验）。

### 7.1 技能包结构（符合规范约定）

| 文件 / 目录 | 作用 | 规范地位 |
| --- | --- | --- |
| `SKILL.md` | 技能身份证：元数据 + 执行指令。引擎**只通过本文件**判断是否调用技能 | 必需 |
| `manifest.json` | 权限声明（文件系统 / 网络 / 工具 / 环境变量） | 原生代码 Skill 必需 |
| `references/` | 分支专属知识库：景区 / 酒店 / 餐饮样本库 + 营销方法论 | 目录约定 |
| `scripts/` | 确定性辅助脚本：合规校验、打包分发 | 目录约定 |
| `license.txt` | 技能包许可与数据来源说明 | 目录约定 |

### 7.2 两种使用形态（同一份 Skill，两种加载方式）

1. 被 Agent 引擎加载
   ```bash
   openclaw skills install ./.agents/skills/wenlv-assistant
   ```
   引擎会把技能名与路径注入可用技能列表，模型按需读取本文件后执行。

2. 被本地 Web 应用加载
   `server.js` 读取本文件与 `references/` 拼成系统提示词，交给本机 Ollama 推理，
   界面由 `public/index.html` 提供。

两种形态共用同一份 SKILL.md 与样本库，更新知识库只改一处，两边同时生效。

### 7.3 技能包自检

在仓库根目录执行：

```bash
node .agents/skills/wenlv-assistant/scripts/validate-skill.js    # 校验 frontmatter 是否符合规范（退出码 0 = 通过）
node .agents/skills/wenlv-assistant/scripts/package-skill.js     # 校验通过后打包为 .skill 分发文件
```

### 7.4 网络与隐私

`manifest.json` 的 `permissions.network.allow` 只放行 `127.0.0.1` 与 `localhost`，本 Skill 运行期间不访问任何外部网络；
推理与数据全部留在本机，符合"本地部署、数据安全导出"的要求。若后续接入公开数据源（如天气），
需在该字段中显式声明域名。
