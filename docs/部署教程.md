# 部署教程（零基础分步版）

> 面向第一次接触本项目的人。每一步都给了 **✅ 预期结果** 自检点；
> 出错时先看本文最后一节的「常见问题排查表」。

两套交付物分开部署，互不依赖：

- **交付物 ②（AIRI 风格网页版）**：简单，只要 Node + Ollama，建议先跑这个。
- **交付物 ①（AIRI 改进版）**：需要先构建 AIRI 源码，耗时较长，并且要先跑起来交付物 ②，
  因为 AIRI 改进版复用它的 Skill 与记忆服务。

---

## 第 0 步：确认电脑上有什么

打开 PowerShell（Win + X → 终端），逐条执行：

```powershell
node -v          # 需要 v18 以上
ollama -v        # 需要能打印版本号
ollama list      # 看本机已有哪些模型
```

**✅ 预期结果**：三条都能打印出版本或列表。
`ollama list` 里如果**一个模型都没有**，第 2 步会帮你拉一个。

> 如果提示"无法将 node 识别为..."，说明没装 Node.js。去 <https://nodejs.org> 下载 LTS 版，
> 安装时保持默认勾选即可，装完**重开一个终端**。

---

## 第 1 步：把项目放到一个路径不含空格的目录

项目本身对路径没要求，但 AIRI 的构建链路对**中文路径**和**空格**偶尔会出问题，
建议放在例如 `D:\wenlv-airi`。

```powershell
# 假设你已经把 wenlv-airi 文件夹放在 D:\
cd D:\wenlv-airi
dir
```

**✅ 预期结果**：能看到 `README.md`、`docs`、`web`、`airi` 四项。

## 第 2 步：准备本机大模型（Ollama）

```powershell
# 启动 Ollama 服务（如果托盘里已经有 Ollama 图标，这步可跳过）
ollama serve
```

> `ollama serve` 会占住当前窗口，这是正常的。**保持它运行**，另开一个终端做后续操作。

拉一个中文对话模型（二选一）：

```powershell
ollama pull qwen2.5:7b        # 约 5.2 GB，中文效果好，推荐
ollama pull qwen2.5:7b      # 约 4.7 GB，生成速度更快一些
```

**✅ 预期结果**：

```powershell
ollama list
# NAME        ID              SIZE      MODIFIED
# qwen2.5:7b  845dbda0ea48    4.7 GB    ...
```

### 可选：视觉模型与向量模型

| 用途 | 命令 | 大小 | 不装的后果 |
| --- | --- | --- | --- |
| 视觉理解（看图识景） | `ollama pull qwen2.5vl:7b` | 约 6 GB | 点「视觉理解」会明确提示"请先 pull 多模态模型"，其余功能不受影响 |
| 向量检索（记忆语义召回） | `ollama pull nomic-embed-text` | 约 274 MB | 记忆自动退回**中文词法检索**，仍可正常使用，只是召回以关键词为主 |

**本项目的一个设计要点**：这两个都是可选的。服务启动时会自动探测本机有哪些模型，
有什么就用什么；缺什么就在界面上显示成橙色状态灯并告诉你补装命令，**不会静默失败，也不会编造结果**。

浏览器会自动打开 <http://localhost:8000>。

**页面自检清单**（对着看一遍，七项都通过说明环境没问题）：

| # | 看什么 | 说明 |
| --- | --- | --- |
| 1 | 页面上站着一个 Live2D 小人 | 鼠标在舞台里移动，**她的视线会跟着你走** |
| 2 | 小人周围漂着一圈词 | 这就是**交互词云**，词的大小不一样 |
| 3 | 顶栏右上角的状态灯 | 「qwen2.5:7b」绿色 = 对话模型就绪 |
| 4 | 点词云里的「杭州」 | 右侧切到"文旅"页签并**自动开始生成方案** |
| 5 | 点小人身体 | 她会做一个动作，底部**字幕条**出现一句话 |
| 6 | 点舞台右上角的「🖼️ 背景」 | 弹出背景选择器：12 个内置背景 + 上传自己的图 |
| 7 | 点舞台右上角的「🧍 形象」 | 弹出形象选择器：3 套 Live2D + 2 套 VRM（先跑过「获取示例模型.bat」才有） |

> 第 6 步是**内置福利**：背景里有 3 张 AIRI 的图和 9 个程序化背景
> （极光 / 波浪 / 樱花 / 星野 / 点纹 / 山水 / 黄昏 / 宣纸 / 纯色）。
> 第 7 步的形象属于**第三方素材**，仓库里不含模型文件——先双击根目录的
> 「获取示例模型.bat」把 3 套 Live2D + 2 套 VRM 装到本机（约 33MB），再回来点这一项。
> 程序化背景是实时用 Canvas 画的，不占素材体积，任意分辨率都不糊。

### 外观怎么用

- **换背景**：舞台工具条「🖼️ 背景」或右侧「🎨 外观」页签 → 「更换背景」。
  想用自己的图，点弹层里的「📤 上传图片」，图片存到 `data/backgrounds/`，**不出本机**；
  鼠标悬停在自定义背景上会出现 ✕，可以删掉。
- **换形象**：舞台工具条「🧍 形象」→ 点任意一张卡片即刻换上。
  选中的形象会**写进当前角色卡**，所以切角色卡时形象跟着换。
- **微调**：右侧「🎨 外观」页签里能调人物大小与位置、切表情，
  点「保存到当前角色卡」就固化了。
- **词云太密**：同一页签里把「显示数量」调到「精简」，或点工具条上的「☁️」直接关掉。

### 换 3D 人物形象

形象选择器里除了 3 套 Live2D，还有一个 **3D 形象（VRM / GLB）** 分组，
内置两套来自 Project AIRI 的 VRM 示例模型。

想用自己的 3D 模型：点选择器左上角的 **「📤 上传 VRM / GLB」**，选一个 `.vrm` 或 `.glb` 文件。
文件存到本机 `data/models3d/`，**不会上传到任何地方**；鼠标悬停在卡片上会出现 ✕ 可以删掉。

| 格式 | 怎么做出来的 | 能做什么 |
| --- | --- | --- |
| `.vrm` | VRoid Studio 等工具导出的虚拟形象 | 视线跟随、眨眼、说话口型、自然站姿 |
| `.glb` | Blender / 各类 3D 工具导出为 glTF 二进制 | 显示与待机摆动（没骨骼就没有口型） |

**不支持 `.gltf`**（文本格式通常还带一堆散装贴图，传一个文件不够）。
如果你手上是 `.gltf`，请在导出时选 `.glb`。

几点提醒：

- 模型**第一次**切过去会自动截一帧存成本机预览图（存在 `data/models3d-previews/`），
  所以第二次打开选择器就能看到缩略图了。
- VRM 的上传体积上限是 **100MB**（服务器端 `MAX_MODEL3D_BYTES` 可调）。
- 模型文件是从本机读进浏览器再回传本机服务落盘，**大模型（20MB+）会有一段等待**，
  界面上会提示"正在读取并保存到本机"。
- 如果传上去发现人物很小或很大，用「外观」页里的「大小」滑块调，再点「保存到当前角色卡」。

> 界面布局说明：舞台上只有**顶部一条工具栏**和**底部一条字幕条**，
> 它们的高度会作为「安全边距」传给词云，所以三者永远不会互相遮挡。
> 如果换了字体或缩放导致哪里看着挤，点工具条上的「🔀」重排一下词云即可。

> 第一次生成会比较慢（要把模型加载进显存）。生成期间界面会走**流式输出**，
> 字是一个一个蹦出来的，不是干等。

**停止服务**：双击 `stop.bat`，或在该终端按 `Ctrl + C`。

## 第 4 步：接入本机语音合成（Qwen TTS）

这一步是**可选**的。不装的话角色只是不出声，其它功能都正常；

### 4.1 确认 Qwen TTS WebUI 在哪

本机路径（按你自己的实际位置调整）：

```
E:\声音\qwen_tts_webui-licyk-20260407
```

### 4.2 以 API 模式启动

Qwen TTS WebUI 默认只开网页界面，**必须加 `--api` 或 `--nowebui` 才提供接口**：

```powershell
cd E:\声音\qwen_tts_webui-licyk-20260407\core

# 只跑 API，不开网页界面（推荐，省显存）
..\python\python.exe launch.py --nowebui --server-name 127.0.0.1 --server-port 7860
```

> 如果你的整合包有「启动.bat」，双击它也可以，但要在 `launch_args.txt` 里确保有 `--api`。
> 本机的 `launch_args.txt` 内容已经是 `--api`，直接用启动脚本即可。

**✅ 预期结果**：终端出现 Uvicorn/FastAPI 的启动日志，监听 `127.0.0.1:7860`。

另开一个终端验证：

```powershell
curl http://127.0.0.1:7860/qwenapi/v1/models
```

**✅ 预期结果**：返回 5 个模型：

```json
{"models":[
  {"name":"Qwen/Qwen3-TTS-12Hz-1.7B-CustomVoice","type":"custom_voice"},
  {"name":"Qwen/Qwen3-TTS-12Hz-0.6B-CustomVoice","type":"custom_voice"},
  {"name":"Qwen/Qwen3-TTS-12Hz-1.7B-VoiceDesign","type":"voice_design"},
  {"name":"Qwen/Qwen3-TTS-12Hz-1.7B-Base","type":"voice_clone"},
  {"name":"Qwen/Qwen3-TTS-12Hz-0.6B-Base","type":"voice_clone"}
]}
```

### 4.3 首次合成会自动下载模型（耐心等）

**这是最容易被误判为"卡死了"的一步**。第一次请求某个模型时，Qwen TTS 会从 ModelScope
下载权重，落盘在：

```
E:\声音\qwen_tts_webui-licyk-20260407\core\cache\modelscope\hub\models\Qwen\
```

`Qwen3-TTS-12Hz-1.7B-CustomVoice` 约 **2.2 GB**（主模型 1.57 GB + speech_tokenizer 651 MB）。
下载期间接口**不返回**，看起来像卡住，实际上磁盘在涨。想确认是否在下载：

```powershell
# 看模型目录大小是否在变大（多执行几次对比）
Get-ChildItem "E:\声音\qwen_tts_webui-licyk-20260407\core\cache\modelscope" -Recurse -File |
  Measure-Object Length -Sum | Select-Object Count, @{n='MB';e={[math]::Round($_.Sum/1MB,1)}}
```

> 目录名里的 `._____temp` 说明还在下；下完会自动改名成正式目录。
> 想更快可以先下小的：`Qwen/Qwen3-TTS-12Hz-0.6B-CustomVoice`。
> 方式：在 Qwen TTS WebUI 网页界面里选这个模型先生成一次，或者在项目里设
> 环境变量 `QWEN_TTS_MODEL` 指定。

### 4.4 验证整条语音链路

```powershell
cd D:\wenlv-airi\web
node -e "fetch('http://127.0.0.1:8000/api/tts',{method:'POST',headers:{'Content-Type':'application/json'},body:JSON.stringify({text:'你好，我是你的文旅向导小文。'})}).then(async r=>{console.log('HTTP',r.status,'bytes',(await r.arrayBuffer()).byteLength,'cached',r.headers.get('x-tts-cached'))}).catch(e=>console.log('FAIL',e.message))"
```

**✅ 预期结果**：`HTTP 200 bytes 123456 cached 0`（字节数视文本长度而定）。
第二次执行同一句会显示 `cached 1`，说明命中了本地语音缓存，不再重复合成。

**回到页面**：点顶栏的「🔊」图标可以切换**自动朗读**（角色每句回复都念出来）；
在「声音」页签里可以试听 5 个内置音色、改语气指令。

## 第 5 步：部署交付物 ①（AIRI 改进版）

> 这一步会克隆 AIRI 源码并完整构建前端，**首次约 10~25 分钟**，且需要联网。
> 建议在闲时做。

### 方式 A：一键构建（推荐）

```powershell
cd D:\wenlv-airi\airi
```

双击 **`一键构建.bat`**（或在 PowerShell 里执行 `pwsh -File scripts\build-airi.ps1`）。

脚本会依次做完五步，每步失败都会明确报错并停下：

| 步骤 | 做什么 | 自检点 |
| --- | --- | --- |
| 1/5 | 克隆 AIRI 源码到 `airi\airi-source` | 目录下出现 `apps\stage-web` |
| 2/5 | 施加文旅智能辅助补丁 | 打印「补丁已施加（幂等，可重复执行）」 |
| 3/5 | `pnpm install --ignore-scripts` + `pnpm run build:packages` | 打印「33 successful」之类的任务统计 |
| 4/5 | `pnpm -F @proj-airi/stage-web run build` | 打印 `✓ built in ...` |
| 5/5 | 补 Live2D Cubism Core | 打印「Cubism Core 已就位」 |

**✅ 最终预期结果**：`airi\airi-source\apps\stage-web\dist\index.html` 存在。

> **为什么用 `pnpm install --ignore-scripts`**：AIRI 的依赖里有 `sharp@0.29.3`，
> 它的 install 脚本在没有 Visual Studio C++ 工作负载的 Windows 上必然编译失败。
> stage-web 的构建用不到它，所以直接跳过全部 install 脚本，
> 再显式跑 `build:packages`（这一步是构建真正需要的）。
> 脚本还会写 `.npmrc` 关掉 `verify-deps-before-run`，否则 pnpm 每次运行前都会
> 重跑 install，又卡在同一个地方。

### 方式 B：用已有的 AIRI 仓库

```powershell
pwsh -File scripts\build-airi.ps1 -RepoDir "D:\airi"
```

只想重打补丁和重构建（依赖已装好）：

```powershell
pwsh -File scripts\build-airi.ps1 -RepoDir "D:\airi" -SkipClone -SkipInstall
```

### 方式 C：手工三步

```powershell
node scripts\apply-patch.mjs "D:\airi"
cd D:\airi
pnpm install --ignore-scripts
pnpm run build:packages
pnpm -F @proj-airi/stage-web run build
```

### 5.2 启动 AIRI 改进版

双击 **`启动.bat`**。脚本会依次确认 Ollama、文旅网页版后端（8000）、
airi-bridge（8787），缺少哪个就在新窗口里帮你起哪个，最后启动 AIRI 网页版（5174）
并打开 <http://127.0.0.1:5174/wenlv>。

**✅ 预期结果**：AIRI 的界面加载出来，顶栏右侧多了一个**地图图标**（文旅入口），
页面底部是「文旅智能辅助」的词云与结果面板。

也可以手动逐个起：

```powershell
ollama serve                                              # 终端 1
cd D:\wenlv-airi\web    ; node server.js                  # 终端 2  (:8000)
cd D:\wenlv-airi\airi\bridge ; node server.js             # 终端 3  (:8787)
cd D:\wenlv-airi\airi\scripts ; node serve.js "D:\wenlv-airi\airi\airi-source\apps\stage-web\dist"   # 终端 4  (:5174)
```

**停止**：双击 `airi\停止.bat`（会一次性结束 5174 / 8787 / 8000 三个端口上的服务）。

### 5.3 在 AIRI 里把提供商指向本机

AIRI 的设置存在浏览器 localStorage 里，需要在界面上点一次（只做一次）：

| 设置页 | 填什么 |
| --- | --- |
| 设置 → 提供商 → 对话 → **Ollama** | Base URL `http://127.0.0.1:11434/v1/`，无需 API Key |
| 设置 → 提供商 → 视觉 → **Ollama** | Base URL `http://127.0.0.1:11434/v1/`，模型选 `qwen2.5vl:7b` |
| 设置 → 提供商 → 语音 → **OpenAI 兼容 / audio speech** | Base URL `http://127.0.0.1:8787/v1/`（**结尾的斜杠必须保留**），API Key 随便填一个非空字符串（如 `local`），Model 填 `qwen-tts-local`，Voice 随便选一个（`alloy` / `nova` 等，桥里做了音色映射） |

> ⚠️ **Ollama 的跨域**：AIRI 是网页应用，浏览器直连 Ollama 时会被 CORS 拦。
> 需要让 Ollama 允许 AIRI 的来源。启动 Ollama 前设环境变量：
>
> ```powershell
> $env:OLLAMA_ORIGINS = "*"     # 或 "http://127.0.0.1:5174"
> ollama serve
> ```

> ⚠️ **语音 Base URL 结尾的斜杠**：AIRI 的 OpenAI 兼容语音提供商在
> 校验时会拒绝不以 `/` 结尾的 baseUrl（它会拼成 `{baseUrl}audio/speech`）。
> 少了斜杠会一直显示"未配置"。

**✅ 验证**：设置页里该提供商显示为已通过校验（绿色），
「语音」模块选择该提供商后，角色说话时用的是本机 Qwen TTS 的声音。

## 常见问题排查表

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 页面打开是空白，状态灯全是灰的 | 后端没起来，或端口被占 | 看 `web` 那个终端窗口有没有报 `端口 8000 已被占用`；换端口：`$env:PORT=8001; node server.js` |
| Live2D 区域是空的，提示"未加载 PixiJS/Cubism Core" | `public/vendor/` 下三个运行时文件缺失 | 确认 `web/public/vendor/` 下有 `live2dcubismcore.min.js`、`pixi.min.js`、`pixi-live2d-display-cubism4.min.js` |
| 提示"本机没有可用的对话模型" | Ollama 里没有非向量类模型 | `ollama pull qwen2.5:7b`，然后点顶栏的「⟳」刷新 |
| 生成特别慢（好几分钟） | 模型没完全装进显存，走了 CPU 混合推理 | 换小模型：`$env:OLLAMA_MODEL="qwen2.5:3b"; node server.js`；或在 `web/server.js` 里调小 `numCtx` |
| 语音请求一直不返回，但 `curl .../qwenapi/v1/models` 是通的 | **显存被 Ollama 占满了**，TTS 模型拿不到显存退到 CPU，速度极慢 | 见下一节「显存不够怎么办」 |
| 角色不出声 | Qwen TTS 没以 API 模式启动 | 见第 4 步；用 `curl http://127.0.0.1:7860/qwenapi/v1/models` 验证 |
| 语音第一次请求"卡住"很久 | 正在从 ModelScope 下载模型权重（2.2 GB） | 见 4.3，看模型目录大小是否在涨 |
| 语音报"未连接"但服务明明开着 | 端口不是 7860 | 设 `$env:QWEN_TTS_URL="http://127.0.0.1:你的端口"` 后重启 `web/server.js` |
| AIRI 构建卡在 `sharp` 编译报错 | 缺 Visual Studio C++ 工作负载 | 脚本已用 `--ignore-scripts` 规避；若你手工跑的，请照做 |
| AIRI 构建时 `cubism.live2d.com` 超时 | 构建需要联网下 Cubism SDK | 构建脚本第 5 步会兜底；实在不行手动放文件，见脚本输出提示 |

## 显存不够怎么办（实测踩到的坑，重要）

**这是本机实测发现的真实问题，不是理论担忧。**

现象：Qwen TTS 服务明明活着（`/qwenapi/v1/models` 能返回 5 个模型），
但一发合成请求就**长时间不返回**；同时 Ollama 的对话生成也变得很慢。

原因：`ollama ps` 显示对话模型占着 **7.8 GB**（`qwen2.5:7b` + `num_ctx=16384`），
而测试机是 **8 GB 显存**。两个模型加起来装不下，后加载的那个被挤到 CPU 上跑，
速度掉一个数量级。

诊断命令：

```powershell
nvidia-smi --query-gpu=memory.total,memory.used --format=csv
ollama ps
```

如果 `memory.used` 已经接近 `memory.total`，而且 `ollama ps` 里有个大模型，
就是这个原因。

三个解决办法（按推荐顺序）：

**① 让 Ollama 用完就卸（最简单）**

```powershell
# 手动立刻卸载当前模型
node -e "fetch('http://127.0.0.1:11434/api/generate',{method:'POST',headers:{'Content-Type':'application/json'},body:JSON.stringify({model:'qwen2.5:7b',keep_alive:0})}).then(r=>console.log(r.status))"
```

或者启动 Ollama 前设短保活时间（例如 60 秒不活动就卸载）：

```powershell
$env:OLLAMA_KEEP_ALIVE = "60s"
ollama serve
```

**② 用小一号的模型**

```powershell
ollama pull qwen2.5:3b            # 约 2 GB，生成快很多
$env:OLLAMA_MODEL = "qwen2.5:3b"
cd web ; node server.js
```

TTS 侧也可以在 Qwen TTS WebUI 里改用 `Qwen3-TTS-12Hz-0.6B-CustomVoice`
（体积约为 1.7B 版的 1/3）。

**③ 把上下文调小，让模型完全装进显存（效果最明显）**

这是实测出来的：同一个 `qwen2.5:7b`，

| `num_ctx` | 实测占用 | 推理位置 |
| --- | --- | --- |
| `4096` | **5.6 GB** | **100% GPU** |
| `16384`（本项目的方案生成默认值） | 7.8 GB | 20% CPU / 80% GPU |

`num_ctx` 决定 KV cache 大小，是显存占用的主要变量之一。把上下文压到 4096 之后
模型能**全部装进 8 GB 显存**，速度提升非常明显。

改法（`web/lib/wenlv.js` 里的 `ollamaOptions`）：

```js
// plan 这一档默认是 numCtx: 16384（因为要装 SKILL.md + 三个样本库切片）
return { temperature: 0.4, numCtx: 8192, numPredict: 4096 };
```

> ⚠️ **别调太小**：`numCtx` 小于系统提示词的长度时，样本库会被截断，
> 模型拿不到完整数据，推荐质量会明显下降（甚至开始编造）。
> 想同时要"小上下文"和"完整样本库"，正确做法是**精简注入的提示词**
> （例如只注入 SKILL.md 里真正参与生成的章节，而不是整份文档），
> 而不是硬压 `num_ctx`。

**④ 错峰使用**

先用对话功能生成方案，等 Ollama 把模型卸了（或手动卸载）之后，再点「语音播报」。
演示录制时建议这样安排，避免录到大段等待。

> **建议**：如果显存 ≥ 12 GB，两个模型可以同时常驻，就没有这个问题。
> 8 GB 及以下建议采用办法 ①+②。

- 所有推理在本机：**Ollama**（对话 / 视觉 / 向量）+ **本机 Qwen TTS**（语音）。
- 所有持久化都在 `web/data/` 下，纯本地文件：

  | 文件 | 内容 |
  | --- | --- |
  | `data/memory.json` | 机体记忆（可随时删除或导出） |
  | `data/cards.json` | AI 角色卡 |
  | `data/tts-cache/*.wav` | 语音缓存（同一句话不重复合成） |

- 服务默认只监听 `127.0.0.1`，**局域网内其它设备访问不到**。
  需要局域网多人演示时设 `$env:HOST="0.0.0.0"`，但请知悉此时同网段设备可以访问，
  "数据不出本机"这个承诺就不再成立。
- `data/` 目录被静态服务显式屏蔽（返回 403），不会被当成静态文件下载走。
