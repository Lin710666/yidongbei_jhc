# 部署教程（零基础分步版）

> 面向第一次接触本项目的人。每一步都给了 **✅ 预期结果** 自检点；
> 出错时先看本文最后一节的「常见问题排查表」。

两套交付物分开部署，互不依赖：

- **交付物 ②（AIRI 风格网页版）**：简单，只要 Node + Ollama，建议先跑这个。**本仓库就是这一份**。
- **交付物 ①（AIRI 改进版）**：需要先构建 AIRI 源码，耗时较长，并且要先跑起来交付物 ②，
  因为 AIRI 改进版复用它的 Skill 与记忆服务。**它不在本仓库内**，见第 5 步的说明。

---

## 第 0 步：确认电脑上有什么

打开 PowerShell（Win + X → 终端），逐条执行：

```powershell
node -v          # 需要 v18 以上
ollama -v        # 需要能打印版本号
ollama list      # 看本机已有哪些模型
```

**✅ 预期结果**：三条都能打印出版本或列表。
`ollama list` 里如果一个模型都没有，第 2 步会帮你拉一个。

> 如果提示"无法将 node 识别为..."，说明没装 Node.js。去 <https://nodejs.org> 下载 LTS 版，
> 安装时保持默认勾选即可，装完重开一个终端。

## 第 1 步：把项目放到一个路径不含空格的目录

项目本身对路径没要求，但 AIRI 那份交付物的构建链路对中文路径和空格偶尔会出问题，
只部署本仓库的话中文路径也能跑，放在不含空格的目录更省事。

```powershell
# 假设仓库根目录放在 D:\yidongbei-3.0
cd /d D:\yidongbei-3.0
dir
```

**✅ 预期结果**：能看到 `server.js`、`package.json`、`start.bat`、`stop.bat`、`README.md`，
以及 `.agents`、`data`、`docs`、`lib`、`public`、`test`、`tools` 这些目录。

## 第 2 步：准备本机大模型（Ollama）

```powershell
# 启动 Ollama 服务（如果托盘里已经有 Ollama 图标，这步可跳过）
ollama serve
```

> `ollama serve` 会占住当前窗口，这是正常的。保持它运行，另开一个终端做后续操作。

拉一个中文对话模型（二选一）：

```powershell
ollama pull qwen2.5:7b        # 约 4.7 GB，中文效果好，推荐
ollama pull qwen2.5:3b        # 约 2 GB，显存占用更小、生成更快
```

**✅ 预期结果**：

```powershell
ollama list
# NAME        ID              SIZE      MODIFIED
# qwen2.5:7b  845dbda0ea48    4.7 GB    ...
```

### 可选：视觉模型与向量模型

| 用途 | 命令 | 大小 | 不装的后果 |
| --- | --- | --- | --- |
| 视觉理解（看图识景） | `ollama pull qwen2.5vl:7b` | 约 6 GB | 点「视觉理解」会明确提示"请先 pull 多模态模型"，其余功能不受影响 |
| 向量检索（记忆语义召回） | `ollama pull nomic-embed-text` | 约 274 MB | 记忆自动退回中文词法检索，仍可正常使用，只是召回以关键词为主 |

这两个模型都是可选的。服务启动时探测本机已装模型，
缺哪个就在界面上亮橙色状态灯并给出补装命令。

## 第 3 步：启动交付物 ②（AIRI 风格网页版）

### 3.1 三个 bat，各管一件事

| 文件 | 什么时候用 | 它会做什么 |
| --- | --- | --- |
| `检测并安装依赖.bat` | **第一次用之前** | 逐项检查 Node.js / Ollama / 三个大模型 / Qwen TTS / 语音模型 / 前端素材，列出缺的，确认后自动下载。已装好的跳过，不重复下 |
| `start.bat` | 每次要开始用 | 按顺序拉起 ①Ollama ②Qwen TTS 语音 ③网页服务，等端口真的通了再自动开浏览器。已经在跑的服务不会重复启动 |
| `stop.bat` | 用完之后 | 关掉网页服务和语音服务（连端口和窗口一起收），保留 Ollama，最后复查端口是否真的释放 |

`start.bat` 会把服务放在带标题的窗口里跑，方便看日志、也方便识别：

```
文旅智能辅助-网页服务     ← 网页服务本体，启动横幅和报错都在这个窗口
文旅-QwenTTS语音服务      ← 语音合成服务（没装 Qwen TTS 就不会有这个窗口）
```

启动完成的输出长这样：

```
[1/5] Node.js v22.19.0  OK
[2/5] 检查本机 Ollama ...
       对话模型：qwen2.5:7b
[3/5] 检查本机已下载的大模型 ...
       对话模型 qwen2.5:7b  OK
       向量模型 nomic-embed-text  OK
       视觉模型 qwen2.5vl:3b  OK
[4/5] 检查本机 Qwen TTS 语音合成 ...
       未运行，正在自动启动 ...
       Qwen TTS 已连接（http://127.0.0.1:7860）
[5/5] 启动网页服务 ...
       网页服务已启动

==================================================
  全部就绪，浏览器已打开 http://localhost:8000
==================================================
```

> 模型检测走的是 `ollama show <模型>` 的退出码，不去解析 `ollama list` 的文本：
> 列表里的名字带标签（`nomic-embed-text:latest`），做字符串前缀匹配很容易漏判。

**页面自检清单**（对着看一遍，七项都通过说明环境没问题）：

> 第 6 步的内置背景共 12 个：3 张 AIRI 的图片加 9 个程序化背景

> 第 7 步的形象属于第三方素材，仓库里不含模型文件：先双击 `tools\获取示例模型.bat`

> 程序化背景是实时用 Canvas 画的，不占素材体积，任意分辨率都不糊。

### 外观怎么用

- **换背景**：舞台工具条「🖼️ 背景」或右侧「🎨 外观」页签 → 「更换背景」。
  想用自己的图，点弹层里的「📤 上传图片」，图片存到 `data/backgrounds/`，不出本机；
  鼠标悬停在自定义背景上会出现 ✕，可以删掉。
- **换形象**：舞台工具条「🧍 形象」→ 点任意一张卡片即刻换上。
  选中的形象会写进当前角色卡，所以切角色卡时形象跟着换。
- **微调**：右侧「🎨 外观」页签里能调人物大小与位置、切表情，
  点「保存到当前角色卡」就固化了。
- **词云太密**：同一页签里把「显示数量」调到「精简」，或点工具条上的「☁️」直接关掉。

### 换 3D 人物形象

形象选择器里除了 3 套 Live2D，还有一个 **3D 形象（VRM / GLB）** 分组，
内置两套来自 Project AIRI 的 VRM 示例模型。

想用自己的 3D 模型：点选择器左上角的 **「📤 上传 VRM / GLB」**，选一个 `.vrm` 或 `.glb` 文件。
文件存到本机 `data/models3d/`，不会上传到任何地方；鼠标悬停在卡片上会出现 ✕ 可以删掉。

| 格式 | 怎么做出来的 | 能做什么 |
| --- | --- | --- |
| `.vrm` | VRoid Studio 等工具导出的虚拟形象 | 视线跟随、眨眼、说话口型、自然站姿 |
| `.glb` | Blender / 各类 3D 工具导出为 glTF 二进制 | 显示与待机摆动（没骨骼就没有口型） |

**不支持 `.gltf`**（文本格式通常还带一堆散装贴图，传一个文件不够）。
如果你手上是 `.gltf`，请在导出时选 `.glb`。

几点提醒：

- 模型第一次切过去会自动截一帧存成本机预览图（存在 `data/models3d-previews/`），
  所以第二次打开选择器就能看到缩略图了。
- VRM 的上传体积上限是 **100MB**（服务器端 `MAX_MODEL3D_BYTES` 可调）。
- 模型文件是从本机读进浏览器再回传本机服务落盘，大模型（20MB+）会有一段等待，
  界面上会提示"正在读取并保存到本机"。
- 如果传上去发现人物很小或很大，用「外观」页里的「大小」滑块调，再点「保存到当前角色卡」。

> 界面布局说明：舞台上是顶部一条工具栏加底部一条字幕条，
> 它们的高度会作为「安全边距」传给词云，所以三者不会互相遮挡。
> 如果换了字体或缩放导致哪里看着挤，点工具条上的「🔀」重排一下词云即可。

> 第一次生成会比较慢（要把模型加载进显存）。生成期间界面会走流式输出，
> 字是一个一个蹦出来的，不是干等。

**停止服务**：双击 `stop.bat`，或在该终端按 `Ctrl + C`。

## 第 4 步：接入本机语音合成（Qwen TTS）

这一步可以跳过。不装的话角色只是不出声，其它功能都正常。

> **通常你什么都不用做**：`start.bat` 会自己找到 Qwen TTS 的安装位置、
> 检测它有没有在跑、没跑就自动拉起来，并等接口真的通了再继续。
> `stop.bat` 也会把它一起收掉。下面几节是排查用的，出问题时再看。

### 4.1 确认 Qwen TTS WebUI 在哪

它是个独立安装的第三方程序，每台机器装的位置都不一样，所以三个 bat 共用一个
探测脚本 `tools\env-detect.bat`，按下面的顺序找：

1. 环境变量 `QWEN_TTS_HOME`
2. 项目根目录的 `qwen-tts-home.txt`（里面写一行安装路径）
3. `tools\find-tts.ps1` 自动扫常见位置：桌面、`桌面\声音`、文档、下载，
   以及各盘根目录、`<盘>:\声音`、`<盘>:\AI`、`<盘>:\tools`

判定「这个目录就是 Qwen TTS」的条件是同时存在 `core\launch.py` 和 `python\python.exe`。

本机实测位置（供参考，你那边按实际调整）：

```
C:\Users\<用户名>\Desktop\qwen-tts-webui
```

自动扫描找不到时，最简单的手动办法是在项目根目录建一个 `qwen-tts-home.txt`：

```
E:\声音\qwen_tts_webui-licyk-20260407
```

想确认探测结果，可以单独跑一次：

```powershell
powershell -NoProfile -File tools\find-tts.ps1
```

### 4.2 以 API 模式启动

一般不用手动做 —— `start.bat` 会调 `tools\start-tts.bat` 在独立窗口里拉起来。
要手动启动的话注意：Qwen TTS WebUI 默认只开网页界面，**必须加 `--api` 或 `--nowebui` 才提供接口**：

```powershell
cd E:\声音\qwen_tts_webui-licyk-20260407\core

# 只跑 API，不开网页界面（推荐，省显存）
..\python\python.exe launch.py --nowebui --server-name 127.0.0.1 --server-port 7860
```

> 如果你的整合包有「启动.bat」，双击它也可以，但要在 `launch_args.txt` 里确保有 `--api`。
> 本机的 `launch_args.txt` 内容已经是 `--api`，直接用启动脚本即可。

**✅ 预期结果**：终端出现 Uvicorn/FastAPI 的启动日志，监听 `127.0.0.1:7860`。

另开一个终端验证：

```powershell
curl http://127.0.0.1:7860/qwenapi/v1/models
```

**✅ 预期结果**：返回 5 个模型：

```json
{"models":[
  {"name":"Qwen/Qwen3-TTS-12Hz-1.7B-CustomVoice","type":"custom_voice"},
  {"name":"Qwen/Qwen3-TTS-12Hz-0.6B-CustomVoice","type":"custom_voice"},
  {"name":"Qwen/Qwen3-TTS-12Hz-1.7B-VoiceDesign","type":"voice_design"},
  {"name":"Qwen/Qwen3-TTS-12Hz-1.7B-Base","type":"voice_clone"},
  {"name":"Qwen/Qwen3-TTS-12Hz-0.6B-Base","type":"voice_clone"}
]}
```

> 注意：这里列出的是这个版本能下载的模型，不代表本机已经下好了。
> 真正能出声的判定标准是下面 4.3 说的缓存目录里有没有权重文件。

### 4.3 首次合成会自动下载模型（耐心等）

这一步最容易被误判为"卡死了"。第一次请求某个模型时，Qwen TTS 会从 ModelScope
下载权重，落盘在：

```
E:\声音\qwen_tts_webui-licyk-20260407\core\cache\modelscope\hub\models\Qwen--Qwen3-TTS-12Hz-0.6B-CustomVoice\snapshots\master\
```

`Qwen3-TTS-12Hz-1.7B-CustomVoice` 约 **4.3 GB**，
`Qwen3-TTS-12Hz-0.6B-CustomVoice` 约 **2.4 GB**（主模型 1.7 GB + speech_tokenizer 650 MB）。
下载期间接口不返回，看起来像卡住，实际上磁盘在涨。想确认是否在下载：

```powershell
# 看模型目录大小是否在变大（多执行几次对比）
Get-ChildItem "E:\声音\qwen_tts_webui-licyk-20260407\core\cache\modelscope" -Recurse -File |
  Measure-Object Length -Sum | Select-Object Count, @{n='MB';e={[math]::Round($_.Sum/1MB,1)}}
```

> **第一次朗读的下载会被自动触发**：双击 `检测并安装依赖.bat`，它发现语音模型缺失时
> 会自动把服务拉起来、发一次极短合成把下载触发掉，并等到下完为止
> （走 `tools\fetch-tts-model.ps1`）。判定"下完了"的标志是存在
> `<缓存根>\<模型目录>\snapshots\master\model.safetensors`，
> 只有 `.incomplete` 文件说明还在下。
>
> 目录名里的 `._____temp` 说明还在下；下完会自动改名成正式目录。
>
> **模型是自动选的**：`server.js` 会自动挑本机体积最小的那档（见「显存不够怎么办」一节）。
> 8 GB 显存的机器会自动用 `Qwen3-TTS-12Hz-0.6B-CustomVoice`，
> 显存充裕的机器想强制用 1.7B，设环境变量 `QWEN_TTS_MODEL` 指定即可：

```powershell
$env:QWEN_TTS_MODEL = "Qwen/Qwen3-TTS-12Hz-1.7B-CustomVoice"
```

### 4.4 合成速度：本地 TTS 比实时慢，这是正常的

本机实测（RTX 4060 Laptop 8 GB，0.6B 模型）的**实时率约 0.45x**，
换算下来大约**每字 0.5~0.6 秒**（文本越长越接近上限）：

| 文本长度 | 合成耗时 | 音频时长 | 每字 |
| --- | --- | --- | --- |
| 约 40 字 | 21 秒 | 9 秒 | 0.56 秒 |
| 约 100 字 | 58 秒 | 26 秒 | 0.58 秒 |
| 约 160 字 | 78 秒 | 41 秒 | 0.48 秒 |
| 约 200 字 | 88 秒 | 42 秒 | 0.48 秒 |
| 约 400 字 | 249 秒 | 121 秒 | 0.61 秒 |

所以页面上的朗读**默认最多念前 600 字**（最坏约 6 分钟），且点击后会弹出一个
「语音正在生成本地音频…已等待 N 秒（长文本更慢，预计 X 秒左右）」的浮层，
把等待时间和预期耗时都实时显示出来（浮层是设计如此，不是卡住）。
想让它更快，只能换更强的显卡或改用云端 TTS（那就违背"数据不出本机"了）。

### 4.5 验证整条语音链路

```powershell
cd /d D:\yidongbei-3.0
node -e "fetch('http://127.0.0.1:8000/api/tts',{method:'POST',headers:{'Content-Type':'application/json'},body:JSON.stringify({text:'你好，我是你的文旅向导小文。'})}).then(async r=>{console.log('HTTP',r.status,'bytes',(await r.arrayBuffer()).byteLength,'cached',r.headers.get('x-tts-cached'))}).catch(e=>console.log('FAIL',e.message))"
```

**✅ 预期结果**：`HTTP 200 bytes 123456 cached 0`（字节数视文本长度而定）。
第二次执行同一句会显示 `cached 1`，说明命中了本地语音缓存，不再重复合成。

**回到页面**：点顶栏的「🔊」图标可以切换自动朗读（角色每句回复都念出来）；
在「声音」页签里可以试听 5 个内置音色、改语气指令。
点「🔊 朗读」后会弹出「语音正在生成本地音频…已等待 N 秒」的浮层，
合成完自动播放并显示总耗时。长文本要等几分钟是正常的（见 4.4）。

## 第 5 步：部署交付物 ①（AIRI 改进版）

> ⚠️ 这一节说的是**另一份交付物**（在 Project AIRI 源码上做的改进），**不包含在本仓库里**。
> 只部署本仓库的话，跳过这一节即可。
> 本节里的 `airi/`、`一键构建.bat`、`scripts/build-airi.ps1`、`apply-patch.mjs`、`airi-bridge`、
> `serve.js` 这些路径都属于那份交付物，在本仓库里找不到是正常的。

> 这一步会克隆 AIRI 源码并完整构建前端，**首次约 10~25 分钟**，且需要联网。
> 建议在闲时做。

### 方式 A：一键构建（推荐）

```powershell
cd D:\wenlv-airi\airi
```

双击 **`一键构建.bat`**（或在 PowerShell 里执行 `pwsh -File scripts\build-airi.ps1`）。

脚本会依次做完五步，每步失败都会明确报错并停下：

| 步骤 | 做什么 | 自检点 |

## 显存不够怎么办（实测踩到的坑，重要）

下面是本机实际复现过的现象。

### 现象：TTS 直接报 500，而不是变慢

在 8 GB 显存的机器上，如果先用 Ollama 拉起 `qwen2.5:7b`（`num_ctx=16384` 时约占 5.5 GB），
再去请求 Qwen TTS，TTS 不是变慢，而是直接崩。Qwen TTS 那边会打印：

```
Some parameters are on the meta device because they were offloaded to the cpu.
RuntimeError: Tensor.item() cannot be called on meta tensors
POST /qwenapi/v1/custom-voice HTTP/1.1" 500 Internal Server Error
```

原因：显存不够时 `accelerate` 会把 1.7B 语音模型的一部分权重 offload 到 CPU，
但这些权重是以 `meta` 张量形态占位的，生成时一取数值就抛异常，整个请求 500。

这条链路容易误判：`/qwenapi/v1/models` 仍然正常返回 5 个模型，
服务看起来"活着"，只有真正合成才炸。所以"语音服务已连接"并不代表能出声。

### 另一条更隐蔽的现象：界面卡很久没反应

如果语音模型能加载但很慢，界面上的表现是"点了一直转、什么都没有"。
原因是旧版本的合成超时设成了 **5 分钟**（`300000ms`），期间界面不给任何反馈。

### 本项目已经内置的处理

`lib/tts.js` 现在会自动规避这个问题，正常情况不需要手动干预：

1. **自动挑最小的模型**：在 CustomVoice / VoiceDesign / Base 各档里选参数量最小的那个。
   8 GB 机器会自动落到 `0.6B-CustomVoice`，7B 对话模型 + 0.6B 语音模型可以同时驻留
   （实测 7609 / 8188 MiB，两者都是 `100% GPU`）。
2. **端点自动回退**：本机 VoiceDesign 只有 1.7B 一档、没有 0.6B，
   所以「声音设计」类音色会自动降级走 CustomVoice 端点（音色仍由 `instruct` 决定），
   而不是硬怼 1.7B 然后把请求打成 500。
3. **超时放宽到 480 秒**：这个值和上面的 600 字上限是绑定的 ——
   实测大约**每字 0.48~0.61 秒**（越长越接近上限），600 字最坏要跑约 370 秒。
   超时若设得比这小，长文本会在快跑完时被误杀成 504，前面几分钟全白等。
   想调可用 `QWEN_TTS_TIMEOUT`。期间界面不是干等，会显示「已等待 N 秒」。
4. **显存充裕想换回 1.7B**：设 `QWEN_TTS_MODEL` 指定具体模型名。

### 诊断命令

```powershell
nvidia-smi --query-gpu=memory.total,memory.used --format=csv
ollama ps
```

如果 `memory.used` 已经接近 `memory.total`，而且 `ollama ps` 里有个大模型，
就是这个原因。

### 还想再省显存时的五个办法（按推荐顺序）

**① 给 Qwen TTS 开 sdpa 加速**

`python\lib\site-packages` 里没装 `flash-attn` 时，注意力会退化成最慢的 `eager` 实现。
在 Qwen TTS WebUI 的 `core\config.json` 里加一行即可换成 PyTorch 自带的 `sdpa`（不需要编译）：

```json
{
    "api_type": "modelscope",
    "attn_implementation": "sdpa"
}
```

**② 让 Ollama 用完就卸**

```powershell
# 手动立刻卸载当前模型
node -e "fetch('http://127.0.0.1:11434/api/generate',{method:'POST',headers:{'Content-Type':'application/json'},body:JSON.stringify({model:'qwen2.5:7b',keep_alive:0})}).then(r=>console.log(r.status))"
```

或者启动 Ollama 前设短保活时间（例如 60 秒不活动就卸载）：

```powershell
$env:OLLAMA_KEEP_ALIVE = "60s"
ollama serve
```

**③ 换成更小的对话模型**

```powershell
ollama pull qwen2.5:3b            # 约 2 GB，生成快很多
$env:OLLAMA_MODEL = "qwen2.5:3b"
cd /d D:\yidongbei-3.0 ; node server.js
```


**④ 把上下文调小，让模型装进显存（效果最明显）**

这是实测出来的：同一个 `qwen2.5:7b`，

| `num_ctx` | 实测占用 | 推理位置 |
| --- | --- | --- |
| `4096` | **5.6 GB** | **100% GPU** |
| `16384`（本项目的方案生成默认值） | 7.8 GB | 20% CPU / 80% GPU |

`num_ctx` 决定 KV cache 大小，是显存占用的主要变量之一。把上下文压到 4096 之后
模型能装进 8 GB 显存，速度提升明显。

改法（`lib/wenlv.js` 里的 `ollamaOptions`）：

```js
// plan 这一档默认是 numCtx: 16384（因为要装 SKILL.md + 三个样本库切片）
return { temperature: 0.4, numCtx: 8192, numPredict: 4096 };
```

> ⚠️ **别调太小**：`numCtx` 小于系统提示词的长度时，样本库会被截断，
> 模型拿不到完整数据，推荐质量会明显下降（甚至开始编造）。
> 想同时要"小上下文"和"完整样本库"，正确做法是**精简注入的提示词**
> （例如只注入 SKILL.md 里真正参与生成的章节，而不是整份文档），
> 而不是硬压 `num_ctx`。

**⑤ 错峰使用**

先用对话功能生成方案，等 Ollama 把模型卸了（或手动卸载）之后，再点「语音播报」。
演示录制时建议这样安排，避免录到大段等待。

> **建议**：如果显存 ≥ 12 GB，两个模型可以同时常驻，就没有这个问题。
> 8 GB 及以下本项目已自动选小模型（见上文「本项目已经内置的处理」），
> 一般不需要再手动调。

### 数据与网络边界

- 所有推理都在本机跑：Ollama（对话 / 视觉 / 向量）、本机 Qwen TTS（语音）。
- 所有持久化都在 `data/` 下，纯本地文件：

  | 文件 | 内容 |
  | --- | --- |
  | `data/memory.json` | 机体记忆（可随时删除或导出） |
  | `data/cards.json` | AI 角色卡 |
  | `data/tts-cache/*.wav` | 语音缓存（同一句话不重复合成） |

- 服务默认只监听 `127.0.0.1`，局域网内其它设备访问不到。
  需要局域网多人演示时设 `$env:HOST="0.0.0.0"`，但请知悉此时同网段设备可以访问，
  "数据不出本机"这个承诺就不再成立。
- `data/` 目录被静态服务显式屏蔽（返回 403），不会被当成静态文件下载走。
