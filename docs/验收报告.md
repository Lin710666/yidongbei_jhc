Live2D 渲染的验法：把 WebGL 画布 `drawImage`
到临时 2D canvas 上，统计非透明像素数（阈值 400/25600）后判定，只判"画布存在"会放水。

> 测试脚本里一处刻意的取舍：点词云用的是 JS 直接派发 `click`，而不是物理点击。
> 因为词云上的词带持续悬浮动画，物理点击的落点会随动画漂移，可能点到相邻的词
> （实测点到「让 AI 先问我」就走成追问分支，永远等不到行程表）。
> 派发 `click` 仍然走页面真实注册的 `addEventListener` 处理器，后面的动作分发、
> `fetch`、流式渲染全是真的，只是去掉了"落点抖动"这个不确定因素。

### 1.4 语音合成（本机 Qwen TTS）：端到端成功
```
[0.0s]    POST /api/tts  文本：你好，我是你的文旅向导小文，欢迎来到杭州。
[102.5s]  HTTP 200 | model=Qwen/Qwen3-TTS-12Hz-1.7B-CustomVoice | cached=0
[102.6s]  ★ 音频成功  172844 bytes | RIFF=RIFF WAVE=WAVE
[0.01s]   第二次同文本 -> HTTP 200 | cached=1 | 172844 bytes
```

要点：

- 返回的是**合法 WAV**（`RIFF` / `WAVE` 头正确），172,844 字节。
- 模型是代码自动挑选的：`Qwen/Qwen3-TTS-12Hz-1.7B-CustomVoice`
  （`pickTtsModel` 优先 CustomVoice，符合设计）。
- 首次 102.5 s = 模型加载约 90 s + 生成约 13 s；Qwen TTS 日志独立佐证：
  `音频生成完成, 耗时: 12.70s`。
- 第二次同文本 0.01 s，`X-TTS-Cached: 1`，本地语音缓存生效。

> 过程中的真实坑（已写进部署教程）：
> 1. 模型首次要下载 2.2 GB，下载期间接口不返回，看起来像卡死。实测 0.6B 版下载耗时约 10 分钟。
> 2. 8 GB 显存装不下 Ollama 的 7.8 GB + TTS 模型。同时常驻时后加载的会被挤到 CPU，
>    实测出现"接口 5 分钟不返回"。用 `keep_alive: 0` 卸载 Ollama 后立即恢复正常。

### 2.4 一个被单独查清的报错（如实记录）

`verify-airi.mjs` 的跳转流程里出现过两条报错：

```
[Live2D] Failed to load model: TypeError: Cannot read properties of null (reading 'addChild')
Failed to load resource: the server responded with a status of 502 (Bad Gateway)
```

为了判断"是不是本补丁引入的"，在另一份交付物（AIRI 改进版，不在本仓库内）里单独写了 `scripts/probe-airi-errors.mjs`：
分别独立打开 `/` 和 `/wenlv`、不做任何跳转，各等 12~22 秒，收集全部报错。

结论：

```
=== / ===        应用挂载: 是   console error (1): WebSocket ws://localhost:6121/ws ERR_CONNECTION_REFUSED
=== /wenlv ===   应用挂载: 是   console error (1): WebSocket ws://localhost:6121/ws ERR_CONNECTION_REFUSED
                 两页 >=400 或失败的请求均为 0，且都没有任何 Live2D 报错
```

所以：

- 那条 Live2D `addChild` 报错是 AIRI 首页在"正在加载就被卸载"的快速导航下的自身时序问题，
  与本补丁无关（本补丁只新增一个页面和顶栏一个链接，不碰 Live2D 场景）。
- `ws://localhost:6121/ws` 是 AIRI 的**可选** mods server channel，
  源码里就是 catch 住只打一条日志的软失败。
- 因此 `verify-airi.mjs` 的"无控制台错误"这一条，改为用独立加载 `/wenlv` 的新页面来判定，
  这才是对本补丁有效的判定方式。
