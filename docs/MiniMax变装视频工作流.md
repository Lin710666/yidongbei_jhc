# MiniMax H3 变装视频工作流

用 MiniMax 的「参考生成」把四样素材合成一段变装视频。
本文是**可照着敲的操作手册**，每一步都写明为什么这么做、错了怎么查。

---

## 0. 最终要得到什么

| 素材 | 作用 | 对应 API 字段 |
| --- | --- | --- |
| 文件1 视频（真人变装） | **动作**：起手 → 星光炸开 → 换装 → 定姿 | `reference_video` |
| 文件2 视频（天台黄昏） | **场景与风格**：暖橙色调、3D 动画质感 | `reference_video` |
| 文件3 图（千夏） | **人物**：身份、发型、发饰 | `reference_image` |
| 文件4 图（午后茶歇） | **变装目标服装** | `reference_image` |

> 为什么必须是「参考生成」而不是「图生视频」：
> 图生视频只能钉住首帧/尾帧，做不到"动作跟着一段视频走"。
> 只有参考生成能同时吃下 参考视频(动作) + 参考视频(风格) + 参考图(人物) + 参考图(服装)。
>
> ⚠️ 官方明确：**图生视频与参考生成互斥**。一旦出现 `reference_*`，就不能再带
> `first_frame` / `last_frame`，反之亦然。混用直接参数错误。

## 1. 拿 API Key（唯一的前置条件）

1. 打开 <https://platform.minimax.io/user-center/basic-information/interface-key>
2. 注册/登录 → 创建一个 API Key（形如 `sk-...`）
3. **确认账户有余额** —— 视频生成是按量付费的，余额为 0 时接口返回 **402**。
   计费页面：<https://platform.minimax.io/docs/guides/pricing-paygo#video>

把 key 存到项目根目录的 `.minimax-key` 文件里（该文件已在 `.gitignore` 中，不会进仓库）：

```powershell
# 方式一：写文件（推荐，不经过对话/剪贴板历史）
Set-Content -Path .minimax-key -Value "sk-你的key" -NoNewline -Encoding ascii

# 方式二：环境变量（只对当前这个终端窗口有效）
set MINIMAX_API_KEY=sk-你的key
```

## 2. 整理素材（必做，官方有硬限制）

```powershell
node tools\prepare-video-refs.js
```

脚本会按官方限制裁剪。**限制来自官方文档 `video-generation-v2-create`：**

| 项目 | 限制 |
| --- | --- |
| 参考视频数量 | ≤ 3 |
| 单个参考视频大小 | ≤ 50 MB |
| 单段参考视频时长 | 2 – 15 秒 |
| **所有参考视频总时长** | **≤ 15 秒** ← 最容易踩 |
| 参考图数量 | ≤ 9（单张 ≤ 30 MB） |
| 宽高比 | 0.4 – 2.5 |
| 帧率 | 23.976 – 60 |

**为什么要裁**：原始两段是 15.6 秒 + 12.3 秒 = **27.9 秒**，总时长限制是 15 秒，
直接提交会被拒。脚本裁成 motion 9.5s + style 5.0s = **14.5s**，
并且丢掉参考视频的音轨（只取动作/风格，音频用不上，还能压体积）。

跑完应看到：

```
motion.mp4      9.52s  2.33MB   动作参考
style.mp4       5.02s  2.65MB   风格参考
                合计 14.54s ≤ 15s ✓
character.jpg          141KB
outfit.jpg              87KB
```

> 脚本里的素材路径是**写死的**（指向你给我的那四个文件）。
> 换素材时改 `tools/prepare-video-refs.js` 顶部的 `SRC` 即可。

## 3. 生成

```powershell
node tools\minimax-video.js --dir .tmp-vid/prepared --out out/变身.mp4 --duration 10
```

可选参数：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--duration` | 10 | 4–15 的整数。H3 单次最长 15 秒 |
| `--resolution` | `2K` | `768P` 或 `2K`。**H3-Max 不支持 2K** |
| `--ratio` | `16:9` | 参考生成下可留 `adaptive` |
| `--max` | 关 | 换成 `MiniMax-H3-Max`（更快，但只有 480P/768P） |
| `--key` | — | 临时指定 key |
| `--out` | `out/minimax.mp4` | 输出路径 |

脚本做四件事：

1. **上传** 四样素材到 `POST /v1/files/upload`（`purpose=video_generation_input`），拿 `file_id`
2. **建任务** `POST /v2/video_generation`，用 `mm_file://{file_id}` 引用素材
3. **轮询** `GET /v2/video_generation/{task_id}`，每 6 秒一次
4. **下载** 成片到 `--out`

> 为什么先上传而不是内联 base64：本机文件没有公网地址，而 base64 会膨胀约 33%，
> 请求体上限 64 MB —— 两个视频加起来就顶到边了。走 `mm_file://` 最稳。
> 注意**上传的素材只保留 7 天**，过期后重新上传即可。

## 4. 提示词是怎么写的（要改的话看这里）

提示词在 `tools/minimax-video.js` 的 `PROMPT` 常量里。写法上有三个要点：

1. **逐一点名每个参考负责什么。** 不点名的话，模型容易把参考视频里的角色也画进来，
   而不是用参考图里的人物 —— 这是这类任务最常见的翻车方式。
2. **明确写"不要用参考视频里的人"**，只取它的动作。
3. **把变装的因果写清**：先穿什么 → 星光炸开 → 换成参考图2 那套 → 定姿。

当前提示词结构：

```
CHARACTER  —— 从参考图1 取身份/发型/发色/发饰，保持全片一致
SCENE&STYLE—— 跟参考视频2：黄昏天台、暖橙逆光、3D 动画渲染
MOTION     —— 跟参考视频1：抬臂 → 星光炸开 → 换装 → 定姿
OUTFIT     —— 星光中换成参考图2 那套（黑白女仆裙 + 猫耳 + 红背包 + 粉色扩音器）
```

## 5. 出错对照表

| HTTP | 官方错误类型 | 含义与处理 |
| --- | --- | --- |
| 401 | `authorized_error` (1004) | Key 不对 / 没带。检查 `.minimax-key` |
| 402 | `insufficient_balance_error` (1008) | **余额不足，去充值** |
| 422 | `unprocessable_entity_error` (1026) | 输入被判敏感内容。**换措辞或换素材** |
| 429 | `rate_limit_error` (1002) | 限流，等一会儿重试 |
| 400 | `bad_request_error` (2013) | 参数不合法。最常见是缺 `text`、或参考与首尾帧混用 |
| 500 | `server_error` (1000) | 服务端问题，重试 |

排查建议：把脚本打印的 `request_id` 一起提供给 MiniMax 支持，他们能定位到具体请求。

## 6. 本工作流的已知短板（提高质量看这里）

**① 人物参考图分辨率太低 —— 这是最大短板**

`character.jpg` 原图只有 **419×717**，`outfit.jpg` 只有 **597×346**，
而输出是 **2K**。参考图这个尺寸，人物细节（脸、发饰、服装纹样）会明显糊。
**换原图立绘/4K 壁纸的收益远大于调任何参数。**

**② 风格参考视频带 B 站水印**

文件2 左上角有 bilibili 水印，模型有可能把它当"风格的一部分"带进结果。
建议换一段没水印的同类素材。

**③ 输出只有 10 秒**

单次生成上限 15 秒，覆盖不了原始 27.9 秒的全部内容。
默认 10 秒是为了把"变装那一整段"完整放下。要更长就分段生成再拼。

**④ 一次不一定成**

参考生成的随机性不小。建议同一套参数**多跑几次**挑最好的一条，
而不是一次不理想就改提示词 —— 改参数之前先确认是"运气问题"还是"提示词问题"。
