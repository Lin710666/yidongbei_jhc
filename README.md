# 浙里文旅 · 海报与行程（v8.0）

把两套能力收到一个项目里：**做宣传物料**（文旅局 / 酒店 / 饭馆）和**做行程规划**（游客）。
一个入口、一个端口、数据不出本机。

```
┌─────────────────────────────────────────────────────────┐
│  门户  http://127.0.0.1:8800/hub.html                    │
│    ├── 海报生成   /            （本项目自己实现）          │
│    └── 旅游规划   /wenlv/       （反代到 :8001）           │
└─────────────────────────────────────────────────────────┘
```

---

## 一分钟上手

```bash
# 1. 部署（装依赖、建目录、生成配置）
node deploy.mjs

# 2. 启动（三个服务一起起，并自动保活）
node start.mjs
```

Windows 用户直接双击 **`启动全部.bat`**。

浏览器打开 <http://127.0.0.1:8800/hub.html>

> **部署脚本可以反复跑。** 每一步都会先探测"是不是已经就绪"，就绪就跳过 ——
> 中途失败不用从头再来。先体检不改动：`node deploy.mjs --check`

## 环境要求

| | 要求 | 没有会怎样 |
|---|---|---|
| **Node.js** | 18 以上 | 跑不起来 |
| **Python** | 3.9 以上，带 Pillow | 出不了图（`Pillow` 是渲染引擎唯一的必需依赖） |
| **uv** | 可选 | 旅游规划后端退回 venv+pip，慢一些但能用 |
| **Ollama** | 可选 | 海报照样出，但文案用内置规则而不是模型写 |
| **npm** | 可选 | 只有改旅游规划前端源码时才需要（`frontend/dist` 已随包发布） |

**关于 Ollama**：项目会**自己把本机的 `ollama serve` 拉起来**，不需要你手动开。
模型不存在时执行：

```bash
ollama pull qwen2.5:7b      # 约 4.7GB，写文案
ollama pull qwen2.5vl:3b    # 约 3.2GB，读照片
```

显存/内存紧张的话，`posterforge/brain.config.json` 里把 `vision` 设成 `null`
就只写文案不读图；两个都设 `null` 就完全不用模型。

## 项目的三层

```
yidongbei_jhc/
├── deploy.mjs          一键部署
├── start.mjs           一键启动 + 保活
├── posterforge/        海报站点（Node，零 npm 依赖）
│   ├── server.mjs       HTTP 服务 + 反代 + 全部接口
│   ├── brain.mjs        模型调用（文案 / 读图 / 版式分析 / 助手对话）
│   ├── public/          前端（原生 JS，无框架）
│   └── ...
├── renderer/           渲染引擎（Python + Pillow，纯函数）
│   └── render.py       render(spec) → 图
└── hikitravel/         旅游规划（React + FastAPI）
    ├── backend/
    └── frontend/dist/   已构建好的前端（部署脚本会直接用它）
```

**为什么海报站点零 npm 依赖**：它只用 `node:http`，没有构建步骤。
改一行刷新就见效，不用等打包。

**为什么渲染是独立的 Python 层**：排版计算和绘制是纯函数，同样的 spec
永远渲出同一张图。模型只决定"生成什么"，几何全由引擎算 —— 这样出图可复现、
可回归测试，也不会因为模型换个版本就版面跑偏。

## 海报能力

### 七种构图

不是"换背景换文案"，是**版面结构**真的不同：

| 构图 | 图的角色 | 特点 |
|---|---|---|
| `fullbleed` 满版压暗 | 铺满整张 | 文字压在图上，风景照最出效果 |
| `axial` 中轴对称 | 铺满 | 全部居中沿中轴排列，仪式感 |
| `split` 上下分割 | 上方图带 | 图字**不重叠**，不需要遮罩，适合写清价格时间 |
| `splitv` 左右分割 | 右侧出血 | 文字在左窄栏，竖构图单品 |
| `focal` 重心环绕 | **悬浮圆角卡片** | **先看图再读标题**（阅读顺序相反） |
| `grid` 网格信息 | 顶部 | 图 + 2×2 信息格，信息密度最高 |
| `typeled` 文字主导 | 不用图 | 居中超大标题 + 留白 |

**41 套模板 → 41 种唯一版面签名**。差异靠三层机制叠加：

```
构图（结构不同） → 变体（留白节奏 / 字号层级） → 逐套精调（每套各占一档）
```

验收脚本 `posterforge/verify-layouts.mjs` 会给每套模板算一个版面指纹
（`对齐|标题Y|字号|标题高|栏宽|分隔线|图文关系`），**断言每套都唯一**。

### 其他

- **AI 底图**：没上传照片时用本地 SDXL-Turbo 生成一张（首次约 20 秒，之后约 6 秒）
- **文案手册**：多页 PDF，含封面/正文/列表/表格/价格/联系/**实拍图页**
- **打卡模板**：给游客做能发小红书/朋友圈的图，1~4 张照片四种排法
- **批量出图**：一套内容分发到各平台尺寸
- **参考图分析**：传一张参考图，模型判断该用哪种版式（手册模式下定调性）
- **历史记录**：回看生成过的图，可下载/删除（清空列表**不删图**）
- **AI 助手**：右下角悬浮球，本机模型对话，可开 Live2D 虚拟形象（默认关闭）
- **广告法预检**：文案含违禁词会在渲染前直接拒稿，并给出一键改写

## 合规红线（这个项目当真的事）

做文旅物料，**编造事实是最大的风险**，所以这些是硬约束：

1. **不编价格、电话、地址。** 用户没给的，渲染出来就是 `○○○` 占位符
2. **广告法禁用词拦截。** 含"最""第一""独家"等会在出图前被拒，并给替换建议
3. **政务口径不润色。** 文旅局物料必须以官方发布为准
4. **食品宣传高压线。** "养生""治疗""纯天然""有机"等不能写
5. **联网素材只作灵感。** Bing 每日壁纸有版权，界面上写明"图片本身不进成品"

## 出问题时

### 页面打不开

```bash
node deploy.mjs --check    # 先看环境
node start.mjs             # 再看服务
```

三个服务会**自己死**（实测日志里是 `^C` 信号，不是崩溃），所以 `start.mjs`
每 20 秒检查一次端口，谁停了就拉起来。日志在 `posterforge/.work/logs/`。

### 改了代码没生效

静态资源有两类缓存策略：

- `ai-ball.js` / `app.js` / `style.css` / HTML / 缩略图 → **no-cache**（每次回源校验）
- 其他 → 长缓存

HTML 里的助手组件引用还带**版本号**（取自文件修改时间），改了就自动换 URL。
**如果还是看到旧版，Ctrl+F5 强刷一次** —— 浏览器里可能存着改之前的旧文件。

### 出图报"连不上模型"

模型不是必需的。看 `posterforge/brain.config.json` 的 `enabled`，
设成 `false` 就完全走内置规则，海报照样出。

### 旅游规划页 404

`hikitravel/backend/.env` 里的 `STATIC_DIR` 必须是 `frontend/dist` 的**绝对路径**，
不设的话后端起来也不服务前端。部署脚本会自动生成，从别的机器拷配置过来则要改。

## 自检

改完东西跑一遍（服务要先起着）：

```bash
cd posterforge
node verify-layouts.mjs          # 版面签名必须每套唯一
node verify-composition-e2e.mjs  # 构图端到端
node verify-analyze.mjs          # 参考图分析
node verify-assistant-v2.mjs     # 助手（球/面板/设置/对话）
node drive-audit.mjs             # 前端全流程
```

**这个项目的验收纪律是"读真实 DOM / 读像素，不看代码下结论"。**
多个 bug（文字压到图上、卡片描边是方角、缩略图和真实产出不一致）
都只有渲出来看才能发现。
