# 文旅智能辅助 Skill（wenlv-assistant）

> 题目编号：JBGS-2026-06 ｜ 题目名称：文旅智能辅助场景
> 基于 **本地开源大模型（Ollama）** 驱动的文旅智能 Skill 系统。

## 一、项目简介

面向文旅行业的景区、酒店、餐饮三大业态，针对消费体验同质化、客源转化效率低、产品创新迭代慢
这三个痛点，用「智能适配、创新迭代、精准创收」重构传统的「人工服务、固化产品、被动经营」运营模式。

项目聚焦两大核心功能（做深不做宽）：

| 核心功能 | 解决痛点 | 对应价值 |
| --- | --- | --- |
| ① 个性化方案规划 | 消费体验同质化 | 游客消费体验升级 |
| ② 文旅营销素材生成 | 客源转化效率低 / 营销获客成本高 | 文旅营销创收增效 |

另有两条贯穿全流程的设计：

- **输出质检**——核对每一条推荐是否真的来自本地样本库，凡是未能核实的都会在界面上标注出来，
  而不是让用户误以为那是真实数据；它同时能反向指出样本库缺哪些条目。
- **异常处理演示入口**——界面上有专门的按钮，可以现场演示"信息缺失时集中追问""目的地不在样本库时降级"。

本地部署是真本地：所有方案与文案均由本机运行的开源大模型生成，不是规则模板，
也不调用任何云端 API，数据全程不出本机，结果可一键导出为 Markdown。

### 引擎规范与开发方式

| 项目 | 说明 |
| --- | --- |
| **开发方式** | 采用 AI Coding（AI 辅助编码）方式开发，开发过程可见于 git 提交历史 |
| **Skill 规范** | 技能产物遵循 AgentSkill / OpenClaw 引擎规范：`SKILL.md`（元数据与执行指令）、`manifest.json`（权限声明）、`references/`（知识库）、`scripts/`（辅助脚本）、`license.txt`；可被 OpenClaw 等支持 AgentSkill 的引擎直接加载 |
| **运行形态** | 同时提供自包含的本地 Web 演示界面，零第三方依赖、无需任何平台账号、无需联网，双击 `start.bat` 即可运行 |

**同一个 Skill，两种加载方式**（详见 `SKILL.md` 第七章）：

```bash
# 形态一：被 Agent 引擎加载（如 OpenClaw / 网易帝王蟹）
openclaw skills install ./.agents/skills/wenlv-assistant

# 形态二：被本地 Web 应用加载（本项目自带，无需引擎）
双击 start.bat        # 或 npm start
```

两种形态**共用同一份 `SKILL.md` 与样本库**，更新知识库只需改一处，两边同时生效。

> **实测踩到的两个坑（已修正，此处留档避免重犯）**：
>
> 1. **`metadata` 必须写成单行 flow mapping**。写成 `metadata:` 换行再跟 `{ ... }` 时，
>    OpenClaw 解析不到，`emoji`、`requires` 全部失效（技能仍显示 ready，但依赖检查形同虚设）。
>    正确写法见 `SKILL.md`，与引擎自带技能（如 canvas）一致。
> 2. **不要声明用不到的 `requires.config`**。曾声明 `config: ["model", "port"]`，
>    导致 OpenClaw 要求这两个键存在于**它自己的**配置里，技能状态退化为
>    `△ Needs setup`、`Visible to model: no`。本项目的模型与端口是自身环境变量，
>    与引擎配置无关，因此只声明真实需要的 `bins`。

### 在引擎中实地运行（本机 Ollama 驱动，全程离线）

本项目已进一步验证：**OpenClaw 引擎可直接使用本机 Ollama 作为推理模型**，并成功读取本技能。
整个过程不涉及任何第三方 API、不需要 API key、不访问外网。

配置要点（写入 `~/.openclaw/openclaw.json` 的 `models.providers.ollama`）：

```json5
{
  models: {
    providers: {
      ollama: {
        baseUrl: "http://127.0.0.1:11434",
        api: "ollama",
        apiKey: "ollama-local",          // 本地 Ollama 的合成鉴权标记，非真实密钥
        models: [{ id: "qwen2.5:7b", name: "qwen2.5:7b", contextWindow: 32768,
                   maxTokens: 8192, input: ["text"],
                   compat: { supportsTools: true, supportsUsageInStreaming: true } }],
      },
    },
  },
}
```

配置后 `openclaw models list` 显示：`ollama/qwen2.5:7b  Local: yes  Auth: yes  default`。

**运行时验证结果**：技能被注入会话的 `<available_skills>` 列表（含描述与路径），
模型可调用 `read` 工具加载 `SKILL.md` 并遵循其中的规范。

> **第三个坑：小模型需要收窄工具集**。OpenClaw 默认 `tools.profile: "coding"` 会暴露约 25 个工具，
> 7B 级模型会被工具描述淹没（实测出现"被要求回复两个字，却去写 `greeting.txt`"的跑偏行为）。
> 解决办法是收窄为只保留技能加载所必需的工具：
>
> ```json5
> { tools: { profile: "coding", allow: ["read"] } }
> ```
>
> 注意：`tools.allow` 是**在 profile 之后**做交集过滤，所以不能与 `minimal` 档同时用——
> `minimal` 档本身不含 `read`，两者叠加会导致"无工具可用"而报错。

### 启动 OpenClaw 引擎（可选）

> 说明：OpenClaw 属于**可选的运行环境**，不属于交付物本体，因此相关辅助脚本**不放在本项目目录内**，
> 由使用者按自己的环境自行安装与启动。以下为在本机验证时使用的命令。

```powershell
# 安装（约 1.1 GB）
npm install -g openclaw

# 启动 Gateway（需保持运行）
openclaw gateway run

# 打开网页控制台（自动带 token 登录）
openclaw dashboard

# 或使用终端聊天界面 / 单次问答
openclaw tui
openclaw agent --agent main -m "<消息>"
```

安装本技能：

```powershell
openclaw skills install ./.agents/skills/wenlv-assistant
```

**在 OpenClaw 中调用本技能**：

技能包提供 `scripts/` 下的两个**确定性脚本**，Agent 用 `exec` 调用它们即可用上本项目的完整能力
（样本库约束 + 输出质检 + 固定模板）：

```bash
# 个性化方案规划
node scripts/generate-plan.js --city 杭州 --days 2 --budget 舒适 --crowd 情侣 --interests 自然风光,美食 --diet 无

# 文旅营销素材
node scripts/generate-marketing.js --product 景区 --platform 小红书 --audience 年轻情侣 --style 种草
```

脚本内部访问本项目本地服务（`http://127.0.0.1:8000`），返回**含质检提示的纯文本**，Agent 原样转述即可。

**在控制台里推荐这样提问**（把命令直接给它）：

```
请执行这条命令并把输出原样展示给我，不要改写、不要复述技能文件：
node "C:\Users\11702\.openclaw\workspace\skills\wenlv-assistant\scripts\generate-plan.js" --city 杭州 --days 2 --budget 舒适 --crowd 情侣 --interests 自然风光,美食 --diet 无
```

> ⚠️ **为什么要写得这么明确——三点均为实测所得**：
>
> 1. **7B 级模型不遵循 SKILL.md 内部的指令段**。仅在 SKILL.md 里写「执行脚本」不够，
>    它会把技能文件当作"待实现的需求"，甚至凭空编造一个 HTML 页面出来（实测耗时 77 秒、产出无关内容）。
>    **把命令直接写进用户消息**才能触发正确行为。
> 2. **不能走 `web_fetch`**。OpenClaw 出于防 SSRF 的安全设计**硬性屏蔽访问私有/内部地址**：
>    ```
>    [security] blocked URL fetch (url-fetch) targetOrigin=http://127.0.0.1:8000
>    reason=Blocked hostname or private/internal/special-use IP address
>    ```
>    实测 `browser.ssrfPolicy.allowedHostnames` 与 `dangerouslyAllowPrivateNetwork` 均**无法放开** web_fetch 的该限制。
>    因此改用技能自带的 `scripts/` + `exec`——这也正是 OpenClaw 规范中 `scripts/` 目录的既定用途。
> 3. **使用 `exec` 会带来系统访问权限**（`tools.allow` 需包含 `exec`）。
>    本项目仅在演示/验证时这样做；若不需要 Agent 直接调用，可把 `tools.allow` 收窄回 `["read"]`。

## 三、技术架构（实现原理）

```
浏览器 demo/index.html（采集表单 → 展示结果 / 质检告警 / 报错）
   │  POST /api/generate
   ▼
本地服务器 server.js（Node，仅监听 127.0.0.1:8000）
   │  ① 按功能读取 SKILL.md + 相关 references（启动后缓存）
   │  ② 组装成"系统提示词"（说明书 + 本地知识库 + 硬性约束）
   │  ③ POST localhost:11434/api/chat（带超时）
   ▼
Ollama 本地推理（localhost:11434，加载 qwen2.5:7b）
   └─ 模型真正"理解需求 + 生成"，返回 Markdown
   ▲
   │  ④ 输出质检：与样本库实体白名单核对 → 编造 / 漏填 / 结构异常项随结果一并回传
   │  ⑤ 前端在结果区顶部用黄色告警条列出质检发现
```

**一个 Skill 的完整形态 = 说明书（SKILL.md）+ 知识库（references）+ 大脑（本地模型）。**
本项目把三者真正串了起来：`SKILL.md` 不再是一张"纸"，而是被 `server.js` 读进内存、
拼成系统提示词喂给本地模型；`references/*.md` 作为可替换的本地样本库，让模型输出可落地。

## 四、功能说明

### 功能一：个性化方案规划
输入目的地、天数、预算、同行人群、兴趣偏好、饮食禁忌，
由本地大模型生成「游玩·旅居·餐饮」一体化方案，含：
行程总览表、逐日行程、费用预估、替代方案与避坑提示。

### 功能二：文旅营销素材生成
输入产品类型、目标平台、客群、风格，
由本地大模型生成 2 个可 A/B 测试的版本（理性卖点版 + 感性情绪版），含：
标题、正文、话题标签、配图建议、行动号召（CTA）。
覆盖朋友圈 / 小红书 / 抖音 / OTA / 公众号 五大平台。

### 演示入口三：异常处理现场演示（「🤔 让 AI 先问我」）

方案面板上有一个专门的按钮：**不填任何需求直接点它**。服务端会走 `type=intake` 分支，
只把 SKILL.md「2.2 需求采集」的规则交给模型，让模型自己按规范输出
**一次性集中追问（带可点选选项）**——把"信息缺失处理"从文档里的一句话变成可见的模型行为。

> 另外，把「目的地」改成杭州以外的城市（输入框可自由填写），即可演示
> "目的地不在样本库 → 退回通用文旅知识并明确标注建议补充本地数据"这条降级路径。

### 贯穿功能：输出质检（本项目可信度的关键）

小模型会编造数据。实测中，它在样本库只有 25 条实体的情况下，凭空生成了
**「东坡美食（人均 70 元）」「老板娘小馆」这类样本库里根本不存在的商家**，
还把住宿条目当作餐厅引用。因此 `server.js` 在结果回传前会做七类自动核对：

| 质检项 | 判定方式 | 发现问题时 |
| --- | --- | --- |
| **推荐项是否来自样本库** | 把三个样本库表格首列的 25 个「名称」按景区/酒店/餐饮**分三类**建库，逐个核对输出中的逐日字段与总览表单元格 | 列出"未能在本地样本库中核实"的名称 |
| **条目类别是否用对** | 午餐/晚餐只允许引用餐饮库、住宿只允许引用酒店库、上午/下午只允许引用景区库 | 指出"该条目来自 X 库却被放在 Y 位置"（例如把民宿当成餐厅） |
| **天数是否写满** | 请求 N 天却只有 M 段 `## Day` | 提示"缺 N-M 天，可能提前收尾或被长度上限截断" |
| **总览表是否有数据** | 「行程总览」表的数据行数是否为 0 | 提示"表只有表头，导出后是空表" |
| **字段是否被占位符敷衍** | 统计填「无 / 待定」以及整段缺失的字段数 | 比例超阈值时提示"样本库条目可能不足以覆盖该天数" |
| **章节是否重复** | 检查 `##` 级标题是否重名（A/B 两版的 `###` 级同名小节不算） | 提示"小模型长文重复退化，建议重试" |
| **表格列数是否与表头一致** | 逐表比对表头与数据行列数 | 提示"该列内容缺失，导出后对应单元格会是空的" |

质检逻辑单独放在 `lib/audit.js`，并由 `test/audit.js` 用**两次真实翻车输出**做回归测试
（编造商家版、只输出 3 天版），确保质检本身不会失灵：`node test/audit.js`。

质检结果以黄色告警条显示在结果区顶部，**不隐藏、不丢弃、也不伪造**——把"模型可能编了"
如实告诉用户。同时提示词的「硬性约束」段也会要求模型只引用样本库内的名称。

> 设计取舍：这里**没有**选择"把未核实的推荐直接删掉"。静默删除会让用户以为输出 100% 可信，
> 比如实标注更危险；标注出来还能反过来变成一份"样本库待补充清单"。

## 七、异常处理设计

**系统级异常**（由 server.js / 前端处理，出错直接提示用户）：

| 异常类型 | 处理方式 | HTTP 状态码 |
| --- | --- | --- |
| Ollama 未安装/未运行 | 返回「请确认 Ollama 已安装并运行」及安装命令 | 502 |
| 模型未下载 | 返回「请运行 `ollama pull qwen2.5:7b`」；前端徽标显示橙色「模型未下载」 | 503 |
| 生成超时（冷启动加载权重太慢） | 提示已等待秒数 + 建议先用 `ollama run` 预热 | 504 |
| 未启动本地服务器 | 前端徽标显示「本地服务未启动（请双击 start.bat）」 | — |
| 模型返回为空 | 提示重试 | 502 |
| 端口被占用 | 打印明确提示，并建议用 `PORT=8001` 换端口 | — |
| **畸形 URL（如 `/%`）** | 返回 400 并保持服务存活（旧版本会直接崩掉整个服务） | 400 |
| 请求体非法 JSON / 非法 type / 过大 | 分别返回 400 / 400 / 413 | 4xx |

> 说明：业务失败不再一律返回 HTTP 200，而是按错误类型给出 4xx/5xx，前端依据 `code` 字段
> 区分"服务没起 / Ollama 没起 / 模型没下"三种状态，避免把排查方向指错。

**模型级异常**（由 SKILL.md 提示词 + 输出质检共同处理）：

| 异常类型 | 处理方式 |
| --- | --- |
| 信息缺失 | 一次性集中追问（带选项），界面上有专门按钮可现场演示 |
| 目的地不在样本库 | 退回通用文旅知识生成，并标注「建议补充本地数据」 |
| 推荐项不在样本库（模型编造） | **输出质检拦下并明确标注**，不再静默放行 |
| 字段被「无」敷衍 | 质检统计后提示，并说明可能是样本库条目不足 |
| 输入矛盾（预算与需求冲突） | 指出冲突点，给出两套方案 |
| 越界/无关请求 | 礼貌说明聚焦范围 |
| 危险/不当内容 | 拒绝生成并说明理由 |

## 八、数据安全与本地化

- **推理全程在本机**：模型（Ollama）与数据都不出本机，**不调用任何云端 API**
- **默认只监听 `127.0.0.1`**：服务不会暴露到局域网，保证"数据不出本机"这个承诺在实现层面成立
  （如需局域网多人演示，可设 `HOST=0.0.0.0`，但请知悉此时同网段设备可以访问）
- **一键导出** Markdown：结果可本地保存、二次编辑
- **样本库可替换**：`references/` 下均为示例数据，正式运营替换为本地真实业态数据即可
- 如需更换模型（更快/更强/更省内存），设环境变量 `OLLAMA_MODEL=qwen2.5:3b` 即可，无需改代码

## 十、已知限制（如实说明）

以下都是明知而未在本版解决的问题，列出来是为了不夸大能力：

| 限制 | 现状 | 影响 |
| --- | --- | --- |
| **非流式输出** | 服务端 `stream: false`，一次性返回完整结果 | 7 天方案实测约需 40 秒，期间只能看到"已等待 N 秒"的计数，看不到逐字输出 |
| **长天数方案写不满** | 样本库已覆盖 5 城（52 景区 / 27 酒店 / 38 餐饮），但 7B 模型在 7 天这类长方案上仍会提前收尾（实测 5~6 天） | 已由**输出质检主动告警**"请求 N 天、实际只生成 M 天"；2~3 天方案可稳定写满 |
| **样本库为示例数据** | `references/` 按城市分节，5 城数据为公开常识整理（票价标「约」） | 正式使用需替换为本地真实业态数据；服务端只注入所选城市那一节，扩充城市不挤占上下文 |
| **模型不主动触发技能** | 在 Agent 引擎中，7B 模型不会按 `description` 自主调用技能 | 需在消息中明确要求读取技能文件或执行脚本（详见「启动 OpenClaw 引擎」节） |
| **输出质检是"检查"而非"纠正"** | 只做白名单核对与结构检查，不修改模型输出 | 能发现并标注编造内容，但不能阻止模型生成它；要根治需要更强的约束或换更大模型 |
| **无并发控制** | 多个请求会同时打到 Ollama | 本地显存有限，同时点多个按钮会互相拖慢；前端已用"生成期间禁用按钮"缓解 |
| **单轮生成** | 每次请求独立，不保留上下文 | 不支持"把 Day 3 换个餐厅"这类追问式修改 |
| **无多用户隔离** | 面向本机单用户演示设计 | 不适合直接作为多人线上服务使用 |

> 若继续迭代，建议顺序：**流式输出** → **样本库扩充到多城市** → **输出质检的自动纠正**。

## 十一、维护提示：改 `.bat` 文件前必读

`start.bat` / `stop.bat` 里有中文提示，而 **cmd.exe 是按当前代码页（简体中文系统为 GBK/936）逐行解析批处理文件的**。
下面两个组合会让脚本直接失效（实测：cmd 会把中文当成命令名，报一堆 `'xxx' is not recognized`）：

| ❌ 不要这样 | 原因 |
| --- | --- |
| 用 **UTF-8** 保存 `.bat` | cmd 按 GBK 解码 UTF-8 字节 → 乱码甚至行错位 |
| 在脚本里用 `chcp 65001` 切换到 UTF-8 | 切换代码页会让 cmd 后续的行读取**字节偏移错位**，解析彻底崩掉 |
| 用 `timeout` 做等待 | stdin 被重定向时 `timeout` 直接报"不支持输入重新定向"并退出，等待失效 |

| ✅ 正确做法 | 说明 |
| --- | --- |
| `.bat` 保存为 **ANSI / GBK** 编码（VS Code 里选 "GB2312" 或 "GBK"） | 与系统代码页一致 |
| 开头写 `chcp 936 >nul` 强制代码页 | 即使控制台被设置成 UTF-8 也能正确显示 |
| 开头写 `cd /d "%~dp0"` | 保证在脚本自身目录执行；否则从别处调用时 `node server.js` 会在错误目录找文件 |
| 用 `ping -n 2 127.0.0.1 >nul` 代替 `timeout` 做等待 | 不依赖 stdin |
| 用 `goto 标签` 代替 `if (...) else (...)` 大括号块 | 多字节字符在括号块里更容易触发解析问题 |

> `.js` / `.md` / `.html` **不受影响**，保持 UTF-8 即可。只有 `.bat` 需要注意。
