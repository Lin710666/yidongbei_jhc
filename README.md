# 文旅智能辅助 v5.0

一个跑在本机的文旅智能助手。左边是 Live2D 或 3D 虚拟向导，右边是对话与功能面板，
所有能做的事都做成了环绕在人物周围的词，点一下就执行。

## v5.0 更新

这一版主要是**把它做成能直接摆进展厅的样子**，另外补上了定位导航。

**开屏（两套模板）**

- 新增开屏页，两套模板随时切换：**🎬 视频主页**（整屏宣传片 + 三个功能入口）
  和 **🛶 形象主页**（暗色氛围 + 竖排菜单 + 右侧真实形象）。
- 三个入口有各自明确的落地页，并且按钮上直接标出会去哪：对话 → 对话页、
  设置 → 角色卡页、API 接入 → 外观页（展开「模型接入」「对外开放」两个折叠区）。
  之前设置和 API 接入都跳外观页，点完会以为"没跳转"。
- 形象主页**与主界面共用同一个舞台**，所以换主页形象时开屏跟着变，不用单独同步；
  开屏期间会把词云/顶栏/侧栏收起来，只留角色与背景。

**视频背景**

- 下载到本机再播（`data/videos/`），**离线可用**；开屏与主界面共用同一份片源与画面模式。
- 三种画面模式：**逆时针旋转 90°**（横拍片源被封装成竖屏时用）、**铺满裁剪**、
  **完整显示**（两侧用模糊的同段视频垫底，不裁内容）。
- **保留声音**，并加了静音开关。注意浏览器只放行"静音自动播放"，所以是
  **先静音起播保证画面，再把开声挂到你第一次点页面/按键**；选择会记住。
- 新增 `npm run fetch:bili -- <BV号> 名字`：从 B 站取流下载并合并音轨到本机
  （需要 `imageio-ffmpeg`，一键部署会装）。**不内嵌、不解析直链**。

**定位导航（新）**

- 新增整页导航（顶栏「🧭 导航」）：**自己实现的极简瓦片地图**（Web Mercator + 平移 +
  缩放 + 打点，零依赖），用高德栅格瓦片（不需要 key，中文注记），走本机 `/api/tile` 代理
  并缓存。
- 定位后按距离列出附近景点，给出**距离 + 方位角 + 十六方位 + 步行估算**，
  并可一键跳到高德／百度／腾讯地图去真导航。
- 定位有三级兜底：浏览器定位 → 手动输入经纬度 → 内置城市起点。**说明**：浏览器只在
  `localhost` 或 HTTPS 下允许定位，用局域网 IP 打开会被直接拒绝（连授权弹窗都没有），
  展会大屏常是这种情况，所以兜底是必要的。
- 页面上明确写着那是**直线距离而非路程** —— 真正的路径规划要有路网或规划 API，不假装能做。

**形象**

- 内置原创的「**江南古风少女**」并设为默认：双环髻与步摇、额前花钿、交领右衽月白上襦、
  青碧缠枝长裙、青花油纸伞，配色取自江南烟雨与青花瓷。纯代码绘制，**不含任何第三方素材**，
  可放心对外展示，任意分辨率都不糊。
- 舞台上的举牌取消了（用户反馈太突兀：比人物还显眼、还挡风景），改成右下角一张小卡片，
  点开才是整页导航。
- 补齐 Live2D 官方示例（`npm run fetch:live2d`），并给所有形象生成预览图
  （`npm run previews:cdp`，用系统 Edge 无头截图，不需要装 Playwright）。

**其它**

- 跨子系统显存仲裁（`lib/gpu.js`）：TTS / Whisper / TripoSR / 深度估计这些独占任务
  与 Ollama 对话之间排队，避免 8GB 显卡上互相挤爆。
- 一键部署：`一键部署.bat`（Python 依赖、示例素材、启动全包）；
  Python 侧依赖显式声明在 `requirements.txt`。
- 修掉两类静默故障：CSS 的 `[hidden]` 被 `display: grid` 顶掉（开屏关不掉、进不去功能页）、
  `stageProblem()` 操作了根本不存在的 `.hidden` 类（加载中/加载失败提示永远不显示）。

## v4.1 更新

v4.1 在 4.0 基础上补的主要是"缺的那几块"：

- 新增「产品研发」。赛题把产品研发列进了五大业务场景，之前只在营销主体里间接带一下，
  严格说不算。现在词云上有独立的「产品研发」组，点进去出一张产品概念卡，含产品名、
  目标客群、组合要素、差异化卖点、定价区间、上新理由、风险与前提。
- 生成排队时不再白等。本机模型同一时刻只服务一个请求，原来后来的请求会在队列里
  白白耗掉自己的超时预算，界面上还只显示"正在生成"。现在会说明在排队、前面有几个，
  而且排队那段不计入生成超时。
- 超时报错改成说人话。原来流式读取读到一半超时，会把 `AbortError` 原样甩给用户，
  界面上只有一句 "This operation was aborted"，看不出发生了什么。
- 4.0 的交互终于有回归测试了。新增 `test/verify-interactions.mjs`（24 项），
  覆盖渐进披露、多选、天数控件、结果卡排版、字色；没有 Playwright 时打印一句
  「跳过」而不是甩一段栈。

v4.0 主要动的是词云和结果展示，交互方式跟 v3.1 比变化比较大：

- 词云默认只留骨架。分组标签和核心功能词先露出来，具体条件词（城市、预算、同行人群这些）
  要鼠标进舞台、或者点开某一组，才淡入显示，不会一上来就被几十个词糊住。
- 条件词改成"选中但不立刻生成"。点一下选中、用红框圈出来，再点一下取消，要出东西得再点
  「个性化方案」或「营销文案」。以前是点一个就跑一次，根本凑不出「杭州 + 舒适 + 亲子」这种组合。
  多选只对「兴趣」组开放（和右侧表单里的兴趣一样是多选），城市、预算、人群、忌口这些本来就互斥。
- 词云字色能自己定。以前只有跟随背景亮度自动切黑字/白字，现在可以手动锁死，
  另外给了 8 个常用色的色板和系统取色器。整套配色都从 `--wc-ink` 一个变量推导，改一处全变。
- 全屏状态下有了结果卡。点核心词之后词云收起，网页底部浮出一张占四分之一高度的半透明卡片，
  左上角写角色名，右上角是朗读按钮。行程方案里 Day 1 / Day 2 并排成一行，其余各块各占整行；
  营销文案的版本 A / 版本 B 分成两列，纵向不用滚那么久。
- 「游玩天数」变成了词云上的控件。词本身带上下箭头，点一下加减一天，不用再去右边面板改数字。
- 修了几个实在的问题：全屏词云时背景露黑底（背景模块没监听容器尺寸变化，全屏不触发窗口 resize）；
  想从「杭州」改点「苏州」却点不中（字幕条每说一句话都会把词云整体重排一遍，词跑掉了）；
  大屏上背景粒子被数量上限截顶，看着比小屏还稀。

主要特点：

- **界面**：虚拟人物站在中间，交互词云环绕在两侧；顶部一条工具栏，底部一条字幕条。
- **服务全部本地**：对话、视觉、向量走本机 Ollama；语音走本机 Qwen TTS；
  记忆和角色卡是本机文件。不调用任何云端接口，也不需要 API Key。
- **零第三方依赖**：只用 Node 内置模块，不需要 `npm install`，没有构建步骤。
- **可换外观**：12 个内置背景、5 套人物形象（3 套 Live2D + 2 套 3D VRM），都支持换成自己的。

## 快速开始

### 第一次用：先补装依赖

双击 **`检测并安装依赖.bat`**。它会逐项检查 Node.js、Ollama、三个本地大模型、
Qwen TTS WebUI、语音模型和前端素材，把缺的列出来，确认后自动下载。
已经装好的会跳过，不会重复下；什么都没缺就直接告诉你"可以启动了"。

### 日常使用：一键启动

双击 **`start.bat`**。它会依次把下面三个都拉起来，最后自动打开浏览器：

| 顺序 | 启动什么 | 窗口标题 |
| --- | --- | --- |
| 1 | 本机 Ollama（对话 / 视觉 / 记忆向量），没运行会自动起 | —— 托盘运行 |
| 2 | 本机 Qwen TTS 语音合成，没运行会自动起 | `文旅-QwenTTS语音服务` |
| 3 | 文旅智能辅助网页服务 | `文旅智能辅助-网页服务` |

然后打开 <http://localhost:8000>。

### 关掉：一键停止

双击 **`stop.bat`**。它会关掉网页服务和语音服务（含它们占用的端口和窗口），
**但按要求保留 Ollama 不动**，结束时还会复查一遍端口有没有真的释放。

**零第三方依赖**：`package.json` 的 `dependencies` 是空的，所以 `检测并安装依赖.bat` 里
没有任何 npm 相关步骤。

### Qwen TTS 装在别的盘？

它是个独立安装的第三方程序，位置因人而异，`start.bat` / `stop.bat` 会自动去找
（常见位置：桌面、各盘根目录、`<盘>:\声音` 等）。找不到时可以手动告诉它，二选一：

1. 在项目根目录建一个 `qwen-tts-home.txt`，里面写一行安装路径；
2. 或设环境变量 `QWEN_TTS_HOME` 指向该路径。

没装 Qwen TTS 也能正常跑，只是虚拟人物不会出声，其它功能不受影响。

### 三层浮层怎么避开彼此

舞台上有三层会浮动的东西：顶部工具条、底部字幕条、词云。
做法是把工具条与字幕条的实测高度当作「安全边距」传给词云布局：

```js
// app.js 的 syncCloudInsets()：量出真实高度
cloud.setInsets({ top: 工具条高 + 34, bottom: 字幕条高 + 30, left: 16, right: 16 });
```

词云的排布边界改用「可用区」（容器减去安全边距），于是三者不会互相遮挡。
字幕条出现/消失时会重新量一次（只在**可见性变化**时重排，不是每个流式片段都重排）。

> 有个容易写错的细节：**人物排除椭圆的圆心必须用「舞台中心」，不能用「可用区中心」**。
> 因为 Live2D 人物站在舞台正中，而"可用区"会被工具栏和字幕条挤得整体上移；
> 两者一旦共用一个圆心，字幕条一出现排除区就跟着往上跑，人物下半身就漏出来被词压住。
> 这个 bug 是被验收脚本里那条「词云不压住人物」抓出来的。

## 外观：换背景 / 换形象

点舞台工具条上的「🖼️ 背景」或「🧍 形象」，或进右侧「🎨 外观」页签。

### 背景（12 个内置 + 自定义上传）

| 类别 | 内容 |
| --- | --- |
| **内置图片（3 张，来自 Project AIRI）** | 温馨茶室 · 粉色直播间 · 精灵森林 |
| **程序化背景（9 个，Canvas 现画）** | 极光渐变 · 动态波浪 · 樱花飘落 · 夜空星野 · 十字点纹 · 山水青绿 · 暖金黄昏 · 宣纸留白 · 纯色（跟随主题） |
| **自定义上传** | 你自己的图片，存到 `data/backgrounds/`，可列出、可删除 |

程序化背景是照着 AIRI 的 `Backgrounds` 组件重写的（`part-animated-wave` → 动态波浪、
`SakuraPetal` → 樱花飘落、`pattern-cross` → 十字点纹、默认色相流动 → 极光渐变），
好处是不用带任何图片素材，放到多大都不糊。

「极光渐变」会**跟随角色卡主色**变色；其余背景保留自己的配色
（樱花被染成绿色、山水被染成粉色都不好看）。

选择器缩略图有两种画法：图片用 `drawImage` 裁切，程序化背景调用
`BackgroundManager.renderStatic()` **只画一帧**（`t = 0.9`，让波浪/极光停在有内容的位置），
一次显示 12 个背景，如果每个都跑动画，GPU 会被白白吃掉。

**预览图**由 `test/gen-previews-cdp.js` 用系统自带 Edge 的无头模式 + CDP 协议截图生成，
**不需要装 Playwright**。原来选择器里每个形象都只是一枚 🧍 图标，得逐个切过去才知道长什么样。

> **关于「合题」的坦白话**：项目需要的是西湖主题形象，而**授权清晰、能下载到的国风
> 二次元模型找不到**。我核实过的来源：Live2D 官方示例库（8 个，全是日式）、
> VTube Studio 内置（猫 + Q 版）、VRM 规范示例（技术模型）、CC0 头像库（文件存在
> arweave.net，本机不可达）、HuggingFace 镜像（没有角色素材）。
> 搜索引擎能找到的国风模型全在付费或授权不明的站点（B 站量贩、素材站），
> 这种用于对外宣传有风险，我不会放进来。
>
> 所以现在的做法是：**形象用画质最好的官方示例模型，西湖主题由场景承担**
> —— 西湖背景（断桥、雷峰塔、柳枝、水面波光）、导航举牌、风景图都是西湖。
> 内置的「西湖船娘」保留了（唯一贴主题的形象），但它是我用代码画的，
> 画质比不过专业插画，所以不做默认。
>
> 如果你有国风模型（买的正版、或自己/团队画的），放进 `public/models/`
> 或走「外观 → 更换形象 → 上传」，它会和上面这些一样出现在列表里 —— 不需要改代码。

预览图不是占位图，是离线渲染出来的真实帧：

```powershell
# 用真实渲染器（PixiJS + Cubism）逐个渲染一帧，存成 models/<id>/preview.png
node test/generate-model-previews.mjs
```

之所以离线生成而不是运行时实时渲染：Live2D 的纹理单张就有 2~3 MB，
让前端为每个模型都起一个渲染器太贵。生成一次、静态复用，选择器就只是贴图，零开销。

选中的形象会**写进当前角色卡**，所以切换角色卡时形象跟着换（角色卡里同时存着 `kind`，才知道该用哪套渲染器）。

### 程序化待机（让它一直在动）

模型自带的 `Idle` 动作是**一段定时循环的动画**：播完之后参数就静止了，看上去像卡住。
从 VTS 导入的那几只更明显 —— akari 只有 1 个 Idle、hijiki 只有 1 个，间隔还很长。
所以除了播动作，还在参数层面持续驱动（`startIdle()`）：

| 行为 | 做法 |
| --- | --- |
| 呼吸 | 优先用引擎自带的（认 `ParamBreath`），模型没配时程序化补上 |
| 微摆 | 头部侧倾 + 重心左右微移 + 身体前后微晃，三条不同周期的正弦叠加 |
| 自主视线 | 鼠标静止 2.5 秒后自己瞟两眼；鼠标一动立刻让给"看着你" |
| 定时小动作 | 每隔约 14 秒抽一个动作播，而不是永远循环同一个 Idle |

两个实现上的硬约束（都是读打包后的引擎代码确认过的，写错不会有任何报错）：

1. 参数只能写在 `beforeModelUpdate` 钩子里。写在 `afterMotionUpdate` 会被紧接着的
   `saveParameters()` 当成新的基准值存下来，于是**每帧叠加、一路顶到参数上限**，
   表现为模型越待机越歪、最后定住。
2. 必须用 `addParameterValueById`（叠加）而不是 `set`。引擎自己的 `updateFocus()`
   正是用叠加把"看向鼠标"写进 `ParamAngleX` 这些参数的，用 `set` 会把鼠标跟随整个抹掉。

代价是衣服/头发的物理（`physics.evaluate()`）在钩子之前跑，不会跟着微摆一起甩 ——
这是为了让上面第 1 条成立而接受的取舍。

待机默认开启，可在设置里关掉（3D 形象走同一套开关，语义一致）。

### 让大模型指挥形象（工具调用）

形象会做哪些动作，**只有浏览器加载完模型才知道**（清单在模型文件里，服务端不解析它）。
所以每次提问时前端会把清单随请求上报，服务端据此做两件事：写进系统提示，
以及在 `avatar_action` 工具收到不存在的动作名时**把可用清单作为错误回给模型**，
让它自己改 —— 而不是"它以为吩咐过了、用户却什么都没看到"。

| 工具 | 作用 |
| --- | --- |
| `avatar_action` | 换表情 / 做动作 / 举牌 |

几个刻意的设计：

- 它**不产生任何文字**，只影响画面，所以系统提示里明确要求模型调用完仍要正常作答。
- 它**不受联网开关管辖**。它跟联网半点关系没有，挂在 `web.enabled` 下面会导致
  "一关联网，连笑一个都做不了"。
- 只给动作组名（如 `Idle`）时在该组内随机播一个；组名要在子串匹配**之前**判断，
  否则说 `Idle` 会被子串匹配抢中 `00_idle` 这个具体动作，语义就从"随机"变成了"就播那个"。
- 因为走的是带工具的管线，界面上那句提示会区分「🌐 联网已开启」和「🧰 工具模式」，
  不会在联网关着时谎报"联网已开启"。

### 导航模式（举牌 + 风景图）

点舞台工具条上的「🧭 导航」，左下角出现导航条。设一个目标景点后：

- 形象**举一块木牌**，牌面上写着目标景点名；
- 舞台背景**换成该景点的风景图**。

牌子是**用代码画出来的**（`public/js/nav-visuals.js`），不是从 VTube Studio 的 `Items`
里拿的 —— 那批道具 PNG 是第三方作者的作品（文件名里带着作者署名），拷进项目里用不合适。
程序化画一块木牌则完全没有这个问题，顺带还省掉了联网下载和离线可用性的麻烦。

风景图有三种来源：

| 来源 | 说明 |
| --- | --- |
| **内置程序化** | 现画一张。按景点名做种子，所以不同景点天色与山形不同，同一景点每次都一样。完全离线 |
| **自备图片** | 把图放进 `data/scenery/`，文件名里带上景点名即可被匹配到（`杭州西湖.jpg`、`西湖-断桥.png`、`hangzhou-xihu.jpg` 都认）。目录里会自动生成一张说明 |
| **联网搜索** | **默认关闭，必须手动点「应用」**。搜到后下载到 `data/scenery/cache/` 再交给前端 —— 直接热链外站图片的话，链接今天能看明天就裂，用户断网后整个背景也废了 |

自备图找不到、或联网搜图失败时，会**如实说明原因并退回内置程序化风景**，
而不是留一片空白。三种来源的图都会被自动裁切铺满（等比放大后居中裁剪），不会拉伸变形。

联网搜图受全局联网总开关节制：总开关关着时直接拒绝并告知原因，不会偷偷发请求。

### 西湖船娘（默认形象）

默认形象是**程序化绘制的原创「西湖船娘」**：汉服、发髻簪花、执油纸伞，
配色取自西湖青绿山水。它随项目分发、不需要下载任何模型文件、任意分辨率都不会糊。

**为什么不用现成的西湖主题角色模型**：能搜到的国风角色模型绝大多数是画师/建模师
的作品，明确禁止商用或未标明授权 —— 本项目是要拿去做对外宣传的，用一个授权不明的
角色站台，风险远大于省下的美术成本。而且本机能访问的镜像里没有西湖主题的角色模型。

它不是"只能看不能用"的图：接口和另外两套舞台完全一致，所以它有呼吸、眨眼、
视线跟随、口型同步、6 个动作（招手/作揖/点头/回眸/撑伞/摇橹）、举牌，
也能被大模型用 `avatar_action` 指挥。

> 如果你有自己的西湖主题 Live2D 或 VRM 模型，在「外观 → 更换形象」里换过去即可 ——
> 这套只是**默认**，不是唯一选择。

### 视频背景（大屏宣传片）

把西湖美景宣传片放进 `data/videos/`，或在外观页直接上传（mp4/webm/mov，单个上限 300MB）。
文件名里带「西湖」的会被标为推荐并优先使用。

**不联网找视频**，这是有意的：网上能免费拿到的西湖实拍片多半来源或授权不明，
宣传片是要对外展示的，素材版权出问题的代价远大于省下的事。文件是你提供的，版权你自己清楚。

目录为空时不会黑屏 —— 背景会自动用**程序化绘制的西湖动态画面**兜底
（远山三层、雷峰塔剪影、断桥、柳枝、水面波光与薄雾），完全离线。

视频播放用真正的 `<video>` 而不是把画面画进 canvas：交给浏览器硬解码器，
4K 也不吃主线程，`object-fit: cover` 直接把"铺满且不变形"做掉。
服务端的视频接口支持 **Range 请求** —— 不做的话浏览器拖动进度条会废，甚至直接拒绝播放。

### 大屏适配与全屏展示

原来的"响应式"只有 `max-width` 断点，也就是**只管窄屏**。1920 以上就没人管了：
字号按 14px 基准写得死死的，4K 上像缩了一圈；侧栏被钉在 360~460px，
大屏上宁可留一大片空白也不肯多给舞台。

现在补上了 `min-width` 那半边：

| 断点 | 调整 |
| --- | --- |
| ≥1600px | 基准字号 16px，侧栏 400~520px |
| ≥2200px（2K） | 基准字号 18px，侧栏 460~620px，工具栏字号跟着抬 |
| ≥3200px（4K） | 基准字号 21px，侧栏 560~780px |

顶栏上的「🖥️ 大屏」进入**全屏展示模式**：藏掉侧栏与工具栏，只留形象与字幕，
并请求浏览器全屏（展厅里没人会去按 F11，而 `.kiosk` 只藏界面元素的话，
地址栏和标签页还挂在投影上）。鼠标移到边缘会浮出顶栏，`Esc` 或再点一次退出。

### 开屏（两套可互相切换的模板）

点顶栏「🎬 开屏」可以随时重播；在外观页可以切换模板，选择会持久化。

**模板 A · 视频主页** —— 整屏播西湖宣传片（没有片子时用程序化西湖动态画面兜底），
中间是标题，下面是三个入口：**对话 / 设置 / API 接入**。定位是大屏宣传：
往展厅屏幕上一放，先让人看到西湖。

**模板 B · 形象主页** —— 以展示虚拟形象为主：暗色氛围 + 角色站在画面里，
左侧竖排菜单。**鼠标移到不同入口时，形象会做出不同的动作**（招手 / 作揖 / 撑伞），
用户还没进主界面就先感受到"这个形象是活的"。

> 关于模板 B 的说明：它的布局思路参考了同类"角色展示型"游戏开始界面的常见做法
> （暗色环境、角色居侧、竖排菜单、悬停有反馈）。**没有使用任何第三方游戏的素材、
> 字体或界面元素**，全部是本项目自己的 HTML/CSS 与程序化绘制的形象 ——
> 直接照搬商业游戏的界面素材会有版权问题，那是不能做的。

开屏只在**第一次**自动弹（"已进入"标记存在 localStorage），刷新直接进主界面 ——
每次都弹的话用户三分钟内就会去把它关掉。`Esc` 也能直接进入主界面。

### 3D 人物形象（VRM / GLB）
| 格式 | 说明 | 能做哪些互动 |
| --- | --- | --- |
| **.vrm** | VRoid / VRM 虚拟形象，带标准化骨骼与表情 | 视线跟随、自动眨眼、说话口型、自然站姿、点头 |
| **.glb** | glTF 二进制单文件 | 整体显示与待机摆动（没有骨骼就没有口型/眨眼） |

内置两套来自 **Project AIRI** 的 VRM 示例模型；也可以**上传自己的模型**。

关于 .gltf：那个格式通常还要带一堆散装 `.bin` 与贴图，
网页上「上传一个文件」这个交互没法把整包带上来。与其让用户传完发现缺贴图，
不如在界面上直接说明「请导出成 .glb 或 .vrm」。

上传校验看的是文件内容，不看扩展名。VRM 与 GLB 本质都是 glTF 二进制，
文件头必须以 `glTF` 开头，扩展名写成 `.vrm` 但内容是别的照样会被拒，
界面会提示「文件头应当是 glTF」，免得改个后缀就写进去一个坏文件。

上传模型的预览图是自动生成的。用户上传的模型只在用户机器上，服务端没有渲染器，
但前端此刻已经把它渲染出来了，所以切过去之后直接截当前这一帧回传落盘
（`data/models3d-previews/`），比再跑一遍离屏渲染省事，截到的也正是用户真实看到的样子。
内置的两套可以一次刷完：

```powershell
node test/gen-3d-previews.mjs
```

T-pose 会掰成自然站姿。VRM 文件的静止姿态就是双臂平举的 T-pose（建模约定），
不加载动画时人物会一直张着手站着。代码用 three-vrm 的 normalized bone
把上臂旋转约 79° 放下，只动上臂，不动小臂与手腕——不同模型的骨骼朝向约定不统一，
猜错轴会把手拧到背后。

three.js 按需加载。three.js 1.3MB 加 three-vrm 0.9MB 一共 2.2MB，
只有真的选了 3D 形象才会 `await import('/js/stage3d.js')`，
默认用 Live2D 的用户完全不会下这两个包。

词云和右侧表单用的是同一份选项常量（`lib/wenlv.js` 的 `OPTIONS` / `DEFAULTS`），
所以两边不会对不上。

点词条时角色会随口应一句（比如点「杭州」会说「杭州的安排交给我，正在翻本地样本库…」），
让点击有即时反馈。

### SSE 事件格式

`POST /api/chat` 与 `POST /api/wenlv/generate` 都返回 `text/event-stream`，
每条事件是 `data: {json}\n\n`，末尾 `data: [DONE]\n\n`。

```
{"type":"start","model":"qwen2.5:7b", ...}   # 开始
{"type":"vision","model":"qwen2.5vl:7b","text":"..."}   # 视觉识别结果
{"type":"memory","hits":[...]}               # 召回了哪些长期记忆
{"type":"delta","text":"..."}                # 增量文本（流式）
{"type":"done","content":"...","warnings":[...]}        # 结束 + 质检结果
{"type":"error","code":"NO_MODEL","error":"..."}        # 出错
```

## 外部 API 接入（可选，双向）

默认情况下本项目**完全本地**：对话、视觉、记忆向量走本机 Ollama，语音走本机 Qwen TTS，
服务只听 `127.0.0.1`。下面两个能力都是**显式开关、默认关闭**，不配就完全不出网。

### 出向：接外部大模型（设置 → 模型接入）

把对话/方案/文案换成云端模型，适合本机显卡跑不动、或想要更强模型的时候。

- 界面里选供应商（19 个预设：DeepSeek、月之暗面、智谱 GLM、通义千问、硅基流动、
  OpenRouter、OpenAI、Gemini、Groq、Mistral、xAI、Together、Perplexity、火山方舟、
  混元、星火、本机 Ollama/LM Studio，以及**任意自定义 OpenAI 兼容端点**），
  填 Base URL 与 API Key，点「测试连接」即可。
- **预设只是"填好初值的表单"**，Base URL 与模型名永远可改。厂商域名会变
  （阿里云百炼 2026 年就把推荐域名从 `dashscope.aliyuncs.com` 换成了
  `{WorkspaceId}.cn-beijing.maas.aliyuncs.com`），写死默认值会变成"用着用着就连不上"。
- 「拉取模型列表」直接问端点要真实可用的模型名，避免手抄出错导致 404。
- 「测试连接」跑三级校验：连通性与模型列表 → 模型名检查 → 真发一次最小对话。
  之所以要第三步：能列出模型 ≠ 能用这个模型，密钥额度、模型权限只有真发请求才暴露。
- **视觉与向量是独立开关**，默认保持本地。绝大多数外部厂商（DeepSeek、Groq、Kimi…）
  只有对话接口；用一个总开关全切过去，记忆检索会当场坏掉。
- 切回本地点一下「切回本机 Ollama」即可，配置不会丢。

配置存在 `data/providers.json`（含 API Key，只在本机）。回传给前端的密钥永远是打码版；
"只改模型名"不会把已存的密钥清掉。

### 入向：把本项目当 API 用（设置 → 对外开放）

开启后，AIRI 等外部程序可以用**标准 OpenAI 接口**调用本项目的文旅能力。

| 接口 | 说明 |
| --- | --- |
| `POST /v1/chat/completions` | 对话，支持 `stream` 流式与图片输入。模型名填 `wenlv-assistant` 表示"用本项目当前配置的模型" |
| `GET /v1/models` | 模型列表 |
| `POST /v1/embeddings` | 文本向量 |
| `POST /v1/audio/speech` | 语音合成，返回 `audio/wav`（走本机 Qwen TTS） |
| `POST /wenlv/generate` | 文旅方案 / 文案 / 追问（SSE），另有 `/memory/*`、`/cards/*` |

- `/v1/chat/completions` 与页面上的对话**共用同一条管线**（视觉 → 记忆召回 → 人设 →
  流式生成 → 落记忆），所以两边行为一致，不会出现"接口问出来的和页面问出来的不一样"。
- 鉴权用 `Authorization: Bearer <令牌>`，默认强制。令牌在开启时自动生成，
  **明文只在生成的那一刻显示一次**，之后只保留打码版。
- 能力逐项勾选，默认只开对话、模型列表与文旅生成；**记忆与角色卡默认关闭** ——
  它们是个人数据，勾上就等于交给持有令牌的一方。
- 服务默认只监听 `127.0.0.1`，所以"对外开放"实际上是"对同机的其它程序开放"。

用法示例（AIRI 或任何 OpenAI 客户端）：

```bash
curl http://127.0.0.1:8000/v1/chat/completions \
  -H "Authorization: Bearer <你的令牌>" \
  -H 'Content-Type: application/json' \
  -d '{"model":"wenlv-assistant","messages":[{"role":"user","content":"杭州两天怎么玩"}],"stream":true}'
```

> 关闭状态下访问 `/v1/*` 返回 403，未带令牌返回 401，未勾选的能力返回 403 并说明去哪勾选。

## 联网（让模型上网查资料）

默认**关闭**。输入框上方有个 🌐 按钮，点一下即开；也可以在「设置 → 联网」里细调。

开启后模型手上多了三个工具（走标准 function calling，本地 Ollama 与外部 API 都支持）：

| 工具 | 作用 |
| --- | --- |
| `web_search` | 联网搜索，返回标题 / 网址 / 摘要。无需 API Key，按 Bing → 百度 → DuckDuckGo 顺序自动挑能用的 |
| `web_fetch` | 抓取指定网页并转成纯文本。摘要里没有具体数字时用它读正文 |
| `find_panorama` | 为一个景点检索 360° 全景图候选（供景区建模用） |

一次联网问答的实际过程（`/api/agent` 会把每一步都推给界面）：

```
用户：杭州西湖要门票吗？
🌐 联网已开启，可用工具：web_search / web_fetch / find_panorama
🔍 调用 web_search：杭州西湖 门票 开放时间
✅ web_search 完成：Bing 搜到 6 条（481ms）
↻ 第 2/4 轮：把工具结果交给模型继续作答
答案：杭州西湖景区免费开放，但灵隐飞来峰、雷峰塔等内部景点单独收费…
```

### 几个关键取舍

- **过程文字不算答案。** 模型调工具前常先吐一句"我先查一下"。它不是结论，
  所以带工具调用的那一轮，正文会被 `round_discard` 事件从答案区撤走、归入步骤说明。
  否则用户看到的结论开头会是一句没头没尾的自言自语。
- **步数封顶 + 重复调用去重。** 模型陷入"再查一次"是常见故障。除最多 N 轮（默认 4），
  对"同工具同参数"的重复调用直接回一句"刚刚做过了"，让它换思路而不是白跑几十秒。
- **要抓的 URL 是模型生成的，属于不可信输入。** 所以强制 SSRF 防护：只允许 http/https、
  只放行 80/443，DNS 解析后拒绝一切内网/回环/链路本地地址（含 `169.254.169.254` 这类
  云元数据地址），重定向**逐跳复检**。没有这层，模型（或提示注入）写一个
  `http://127.0.0.1:7860/...` 就能把本机服务当它的内网代理用。
- **失败不抛异常，而是变成"工具的输出"回给模型。** 模型看不到异常，只会看到空白然后开始编。
  把错误当结果回传，它才有机会换个关键词重试。
- **搜索不用 API Key。** 直接解析各家 HTML 结果页。Bing 与百度排前面是因为中文景点覆盖最好；
  国内网络下 DuckDuckGo 常被重置，顺序错了会出现"明明能搜却说搜不到"。
  三家的失败原因会一起报出来，便于区分是网络问题还是页面结构变了。

配置存在 `data/prefs.json`。任一搜索源都可用时不需要任何 Key；
要更稳可以设 `SEARXNG_URL` 指向自建 SearXNG。

## 位置（可选：你在哪、景点在哪个方向）

在「设置 → 位置」里操作，算出来的方位会同时显示在**舞台左上角的 HUD**，
以及（用 3D 形象时）**角色脚下的指北环与方位箭头**。

位置来源有三种，**可信度差别很大，界面上会如实标出来**：

| 来源 | 怎么来 | 精度 | 是否出网 |
| --- | --- | --- | --- |
| 浏览器定位 | 点「📍 获取我的位置」，浏览器弹窗授权 | 准（GPS/WiFi），带 ±N 米 | 否，只落本机磁盘 |
| 手动坐标 | 面板里直接填经纬度 | 取决于你填的 | 否 |
| IP 估算 | 点「🛰️ 用 IP 估算」 | **只到城市级**，可能偏几十公里 | 是，请求第三方定位服务 |

所以：**IP 估算默认关闭**（它属于"出网"）；浏览器定位默认可用（数据不出机器，
而且点击 + 授权两步本身就是同意）。位置存在 `data/location.json`，带来源与时间戳 ——
超过 10 分钟会被标成"已过期"，回答里必须说明，不能把半小时前的坐标当成"你现在在哪"。

**景点坐标先查内置表**：覆盖样本库 5 个城市（杭州 / 苏州 / 成都 / 丽江 / 西安）的主要景点，
断网也能演示。表外地点会返回明确失败原因；开启联网后可走 OSM 在线地理编码补查。

关于数值的两点说明（都写进了返回值，别当成导航数据用）：

- 距离用 **haversine**（球面大圆距离），不是平面勾股。
- 方位是**地图方位**（正北 0°、顺时针），**没扣磁偏角**；国内一般差 2~6 度。

### 位置 MCP 服务

`mcp/location-server.js` 是一个**零依赖的 MCP 服务**（JSON-RPC over stdio），
把位置开放给任何支持 MCP 的客户端（Claude Desktop / Cursor / Agent 框架）：

| 工具 | 作用 |
| --- | --- |
| `get_location` | 返回经纬度、来源、精度说明与时效（`fresh`） |
| `distance_to_spot` | 返回到某景点的距离与方位，并带上"这个结果有什么局限" |

它直接读 `data/location.json` —— 与网页端同一个文件，两个进程不需要互相调用。
注册配置见 `mcp/README.md`。

```bash
node mcp/location-server.js     # 或 npm run mcp:location
```

## 景区全景（可选：把景点变成能环视的三维场景）

在「设置 → 景区全景」里操作。用一张 **360° 等距柱状全景图**（宽高比 2:1）搭出
可环视的场景，再用单目深度模型把画面撑出起伏。

### 立体是怎么来的

不是把照片铺在地上，而是**用深度逐顶点推球面半径**：

```
普通全景球：半径处处相同 → 贴了照片的空心球，没有立体感
这里：     每个顶点的半径由该处深度决定
           近处凸向观察者、远处退到背景 → 照片里的山、树、建筑都成了有厚度的浮雕
```

逐顶点推半径才是与全景几何一致的做法。把照片压成"地面高度图"不成立——
全景里绝大多数内容是**竖直方向**的信息（天空、远山、建筑），压成地面高度既不对也难看。

实测：1024×512 的全景，18721 个顶点，半径从 14.1 撑到 41.6（跨度 27.5），
在 RTX 5060 上深度推理约 0.8 秒。

### 三种来源（界面上会如实区分）

| 来源 | 说明 | 可靠性 |
| --- | --- | --- |
| 联网检索 | 用图片搜索（Bing / 百度）找直链 → 下载 → **量宽高比**，只接受 2:1 左右 | 取决于那个景点有没有公开可用的等距柱状图 |
| 上传 | 你自己提供一张 2:1 全景图 | 最可靠，演示首选 |
| 程序化生成 | 离线合成一张（天空/云/三层远山/地面），**明确标注"非实拍"** | 永远可用 |

> **一个必须说清楚的现实**：实测中文景点在公开网络上基本找不到可自由获取的
> 等距柱状全景图 —— 中文全景平台（720云等）都只给 JS 查看器、不给直链，
> 图片搜索回来的全是普通照片（实测 1.33~2.27 的各种比例）。
> 所以「联网检索」会**正确地全部拒掉**并列出"试过哪些、为什么不行"，
> 而不是硬塞一张会变形的图给你。要真实景演示，请用「上传」。

### 为什么必须量尺寸

判定"能不能当环境球"只有一条硬指标：**宽高比接近 2:1**。
所以下载后要读图片头把尺寸量出来（手写解析 PNG/JPEG/WebP/GIF，零依赖），
不合格的**直接丢弃、不写缓存** —— 否则缓存里会堆一堆贴上去就变形的废图，
下次还优先命中它们。只看 URL 后缀是不够的。

### 需要一次性的模型下载

```powershell
npm run fetch:depth    # 约 95MB，从 hf-mirror 取
```

深度推理跑在 Python 里（torch + transformers）。本项目**不内置 Python**，
而是自动发现本机已有环境（`WENLV_PYTHON` → 项目内 `tools/py` → 本机 AI 环境 → PATH）。
找不到时「检测深度环境」会明确告诉你缺什么；此时全景**仍可环视**，只是没有起伏。
详见 `models/README.md`。

## 图片转 3D（可选：一张图生成三维模型）

在「设置 → 图片转 3D」里操作：选一张图 → 点生成 → **自动加入「外观 → 更换形象」的模型列表**，
可以直接选中查看。全程本机推理，图片不会上传。

用 **TripoSR**（单图前馈重建，不需要多视角）。默认**烘焙贴图**，产物是带内嵌贴图的 GLB；
关掉「烘焙贴图」则退到顶点色（文件更小、快约 25 秒）。

### 一次性准备

```powershell
npm run fetch:triposr     # 权重约 1.6GB，从 hf-mirror 取
```

还需要一个带 `torch + trimesh + omegaconf + PyMCubes` 的 Python 环境。
本项目**不内置**，建法与依赖清单见 `models/README.md`；
「检测运行环境」会明确告诉你缺哪一样。

### 三个踩过的坑（都写进代码注释与测试了）
**① `torchmcubes` 没有 Windows 预编译包。** TripoSR 靠它做等值面提取，
而 `pip install torchmcubes` 直接报 No matching distribution，自己编译要 MSVC。
所以改用 **PyMCubes**，并在 `import tsr` 之前往 `sys.modules` 注入一个同名垫片 ——
不改 vendored 源码，补丁只在一处、显式可见。

> 注意 PyPI 上 `mcubes` 与 `PyMCubes` **是两个不同的库**。装错了会一路跑到
> 提取网格时才炸，报错还指向别处。worker 里专门检测并给出正确的卸载/安装命令。

**② 轴序：不预交换的话模型会悄悄转 90°。** PyMCubes 返回的顶点是按数组下标
`(d0,d1,d2)`，而 TripoSR 的 `isosurface.py` 里有一句 `v_pos[..., [2,1,0]]`，
那是给 torchmcubes 的返回约定做的补偿。换掉后端之后这句仍会执行，等于**换了两次**。
用一个已知位置的体素验证过：不预交换 → 中心 `x=0.801 z=0.199`（错位），
预交换 → `x=0.199 z=0.801`（正确）。

**③ TripoSR 是 Z 轴朝上，three.js/VRM 是 Y 轴朝上。** 出处是 `tsr/utils.py` 的注释
（"x back, y right, z up"）。所以要的是**循环置换** `(x,y,z)→(y,z,x)`
（行列式 +1 的真旋转，不会镜像）。验证方式是拿输入图的宽高比当标尺：
置换后 X/Y = 1.058/0.800 = **1.322**，输入图 410/310 = **1.323**。

**④ 贴图烘焙在 GPU 上是坏的（官方代码的 bug）。** `tsr/bake_texture.py` 里
`positions = torch.tensor(...)` 把位置张量建在 **CPU** 上，而 `scene_code` 在 CUDA 上，
走到 `grid_sample` 就报 `Expected all tensors to be on the same device`。
处理方式与 torchmcubes 垫片一致：不改 vendored 源码，把那个函数替换成逐行相同、
只多一个 `device` 参数的版本。

**⑤ `xatlas.export` 只写 OBJ，不写 GLB。** 之前用 `.glb` 当扩展名喂给它，
结果文件内容其实是 OBJ 文本（文件头是 `v 0.557...`）——
而项目的模型库会校验 glTF 魔数，于是表现成"烘焙成功却登记不进去"。
改成用 trimesh 建一个带 `TextureVisuals` 的网格再导出，贴图会被内嵌进 GLB。

> 顺带修掉一个更隐蔽的：按"要烘焙"取出来的网格是 `has_vertex_color=False`，
> **它本身没有颜色**。烘焙一旦失败就直接导出它，会得到一个**灰模**。
> 现在失败时会重新取一次带顶点色的网格。

### 关于显存

8GB 卡上，**其它程序占着显存时**实测：

| 分辨率 / 分块 | 结果 |
| --- | --- |
| 192 / 4096 | `CUDA error: unknown error`（显存不够） |
| **160 / 2048** | ✅ 成功，约 1.4 万顶点，1~2 分钟 |

所以默认值是 160/2048。显卡空着可以调到 256 拿更细的网格。

> 顺带一提：CUDA OOM 的提示常建议设 `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`，
> 但**本机不要开** —— torch 2.11+cu128 + RTX 5060 上开了会改成抛
> `CUDA error: shared object initialization failed`，那是个更难查的错。

### 去背景失败不会让整个任务失败

去背景（rembg）是**增强项**：它挂了会改用原图继续推理，并在结果里如实标注
`removeBgFailed`。实测本机内存紧张时 onnxruntime 会抛
`BFCArena AllocateRawInternal`，那时让整个任务失败是最糟的选择。

## Blender 动画（可选：在 Blender 里生成移动动画并回传网页）

在「设置 → Blender 动画」里操作。通过 **MCP** 驱动你已装的
「MCP for Blender」v1.6 插件，在 Blender 里建一个会绕圈巡逻的小人、打好关键帧、
导出 glTF，回传网页后用 three.js 的 **AnimationMixer** 循环播放。

生成后同样加入「外观 → 更换形象」，选中即可看到走动动画。

### 必须先让 Blender 跑起来

```powershell
npm run blender:start     # 会弹出 Blender 窗口并自动开启 MCP 服务
```

**为什么一定要图形界面**：插件源码里写得很明确 —— `blender -b`（后台模式）下
**命令永远不会被执行**。它的命令队列靠 Blender 主线程的定时器排空，而后台模式没有事件循环。
所以「弹出一个 Blender 窗口」是这个功能的前提，不是偷懒。

脚本是幂等的：已经在跑就不会再开第二个。

### 协议（读插件源码得到的，不是猜的）

| 项 | 值 |
| --- | --- |
| 传输 | TCP `127.0.0.1:9876` |
| 请求 | `{ "type": "<命令>", "params": { ... } }` |
| 响应 | `{ "status": "success"\|"error", "result": ... }` |
| 本功能用到的命令 | `ping` / `get_scene_info` / **`execute_code`** |

### 两个踩过的坑

**① `execute_code` 不返回 Python 的值，只回 stdout。** 插件实现是
`with redirect_stdout(buf): exec(code); return {"executed": True, "result": buf.getvalue()}` ——
返回值被丢掉了。所以结构化结果只能自己在代码里 `print` 一行带标记的 JSON。
而且导出日志也混在 stdout 里，必须**从后往前找标记行**，不能取最后一行。

**② 一次命令一条连接。** 插件的响应是从定时器回调里 `sendall` 出去的，
多条命令共用一个连接时响应可能交错。每次开新连接最简单也最稳（本机回环，开销可忽略），
换来的是"响应一定属于这次请求"。

### 关于"可循环"

移动动画最容易翻车的是**首尾不接**：走直线的话循环时会有一次瞬移。
所以让小人**绕圈巡逻**、朝向始终沿切线，并且关键帧**包含 t=0 与 t=1 两端** ——
浏览器实测起点与终点都是 `(2.400, 0, 0)`，完全对齐。

> 第一版写成 `range(1, frames+1, step)`，最后一帧只落在 t=0.972，循环就是断的。

## 听觉（可选：用说话代替打字）

进右侧「🔊 声音」页，打开「听觉」开关，输入框旁边就会出现 **🎤**。
点一下开始录，再点一下结束——识别出的文字会**追加**到输入框，确认后再发送。
按 `Esc` 可以取消录音。

用的是**本机** Whisper，全程离线，音频不出本机。默认关闭。

### 一次性准备

```powershell
npm run fetch:whisper
```

约 1GB（默认 `openai/whisper-small`，走 `hf-mirror.com` 镜像）。
嫌大可以换更小的模型：

```powershell
$env:WHISPER_MODEL='openai/whisper-base'; npm run fetch:whisper
```

页面上有「检测环境」按钮。**它做成按钮而不是自动跑**，因为真探测要起一次 Python
（光 `import torch` 就要十几秒），每次打开页面都跑一遍会让人以为程序卡住了。

### 音频链路：为什么在前端转成 WAV

```
MediaRecorder 录 webm/opus
   → 前端用 AudioContext 解码
   → 重采样成 16kHz 单声道 16-bit WAV
   → base64 交给 POST /api/stt
   → 服务端只读 WAV，不依赖 ffmpeg
```

浏览器普遍不支持直接录 WAV，而服务端如果要解 webm/opus 就得依赖 ffmpeg ——
这台机器上不一定有。所以把格式转换放在前端做，后端只需要能读 WAV，
用 Python 标准库的 `wave` 模块就够了。代价是前端多一段重采样代码（`public/js/voice.js`），
但换来的是"后端零额外依赖"。

### 为什么默认关闭

那个模型约 1GB，而且载入要吃内存。项目的一贯原则是"不联网、不装东西也能用，
额外能力要用户自己点头"，所以听觉、联网、IP 定位、对外开放这几项默认全关。

关着的时候不只是界面隐藏按钮：`lib/stt.js` 的 `transcribe()` 会在**做任何工作之前**
就返回"未启用"（连临时音频都不落盘）。把开关判断放在库层面而不是路由层面，
是为了让"关着就一定没动静"这件事在代码结构上成立 —— 将来别的调用方
（MCP、命令行）也绕不过去。

## 显存仲裁（8GB 卡上最要命的那个问题）

本机只有 8GB 显存，而项目里有**五个**地方要用同一张卡：Ollama（对话/视觉/向量，
默认 `keep_alive` 30 分钟常驻）、Qwen TTS、Whisper、TripoSR、深度高度图。
两个同时进来就爆显存，而**爆显存的表现极其难查** —— 报错指向别处
（"模型没完全装进显存"、"被别的程序抢了算力"、CUDA 栈），用户看到的是"随机失败"。

`lib/gpu.js` 做两件事：

| 机制 | 说明 |
| --- | --- |
| **读写锁** | 吃显存的任务（TTS/Whisper/TripoSR/深度图）是**独占**，同一时刻只允许一个；Ollama 的对话/视觉/向量是**共享**，独占期间必须等 |
| **写者优先** | 一旦有独占任务排队，新来的共享请求要让路 —— 否则一个持续提问的界面会让"图片转 3D"永远排不上队 |
| **优先级插队** | `user`(100) > `audio`(60) > `background`(10)。用户在界面上点的活能插到后台跑的深度图前面 |
| **Ollama 让位** | 独占任务开工前把常驻模型请出去（`keep_alive: 0`），干完再预热回来 |

两个容易做错的细节（都写进代码注释与测试了）：

1. **卸载不是立刻生效。** Ollama 收到请求到真正释放显存有一个短暂窗口，
   紧接着启动 Python 会撞上残留占用 —— 所以卸完要等一小会儿（默认 900ms）。
2. **预热要防抖。** 连着跑三个独占任务时不能"卸-装-卸-装-卸-装"。
   只有最后一个释放后才安排预热，且延迟一小段时间等确认没有新任务再真的热。

界面上的 `/api/status.gpu` 会如实报告：谁占着卡、谁在排队、Ollama 有没有被请出去。
用户遇到"点了没反应"时，一眼能看出是在排队而不是卡死了。

显存充裕的机器可以在「设置」里关掉它（`gpu.exclusive = false`）——关掉是**零开销**的，
连让位都不做。

## 本地优先（本地与外部 API 不冲突）

三条口径：

1. **默认全走本地。** 外部 API 只是"用户逐项指定时才启用"的可选项，
   不做任何自动兜底或自动切换 —— 用户对"数据出不出本机"的判断不该被动摇。
2. **两条路的资源不在一个池子里。** 外部 API 调用**不经过**本地显存闸门：
   让它去排本地的队是纯粹的添堵（用户配外部 API 就是为了分流）。
   所以闸门只包本地的 Ollama 分支。
3. **外部生效时不再白占本地显存。** 对话/视觉/向量**三项都**切到外部之后，
   本机模型完全用不上，却还按 `keep_alive` 占着约 5GB —— 这时会主动请它们出去。
   判据刻意是"三项全外部"而不是"对话是外部"：绝大多数外部供应商只有对话接口，
   视觉与向量仍走本地，只看对话就卸载会把记忆检索当场打回冷启动。

`/api/status` 里的 `ollama.localFirst` 直接给出结论（每项能力走哪条路、能不能退回本地），
前端不必自己复刻一遍判断逻辑 —— 复刻错了会显示"走本地"而实际走了外部，
那等于让用户在一个错误前提上做隐私判断。

| `avatar.js` | 形象动作扩容与导航模式。钉的是几个**曾经真实踩过、且表现极具迷惑性**的坑：动作文件都在磁盘上但 `model3.json` 里没有 `Motions` 声明（运行时一个都播不了）；口型参数被写死成 `ParamMouthOpenY`（实测有 4 种不同写法，其中 `mao` 用的是 `ParamA`）；`LipSync`/`EyeBlink` 组**存在但 `Ids` 是空的**（VTS 的模型就是这样，结果是口型不动、眼睛不眨且不报错）；待机的参数驱动若挂在 `afterMotionUpdate` 上会被 `saveParameters()` 存成基准值从而每帧累加。另外覆盖自备风景图的文件名匹配与**路径穿越防护**、以及 `avatar_action` 的名字校验（编造动作名时要把可用清单回给模型） |
| `stt.js` | 听觉。主体不依赖 Python：WAV 头解析、重采样、base64 输入解析、开关关闭时必须拒绝、文件/格式/体积/并发等失败路径的中文报错、临时文件清理，以及 worker 在"模型目录不存在 / 目录在但缺权重"两种情形下的**结构化 JSON 与退出码契约**。需要真起 Python 的部分（真实排队、环境探测、端到端识别）默认跳过，设 `STT_REAL=1` 开启，端到端再加 `STT_E2E=1` —— 光一次 `import torch` 就要十几秒，放进默认链会让整条测试慢到没人愿意跑 |
| `gpu.js` | 显存仲裁。钉的是**锁的语义**而非"能不能跑起来"，因为这类 bug 平时完全看不出来，只在两个任务刚好撞上时随机失败：独占是否真的串行、独占期间共享请求会不会偷偷跑掉（= 还是抢显存）、已排队的独占会不会被新来的共享插队（= 读者饿死写者）、高优先级能不能插到低优先级前面、Ollama 让位与预热是否只做一次、关掉仲裁后是不是零开销、排队超时是否给可操作的错 |
| `display.js` | 大屏适配 / 西湖形象 / 视频背景 / 开屏。这一组功能全是"看不出来坏没坏"的那类，所以钉的是具体判据：大屏断点是否真的存在（原来只有窄屏那半边）、三套舞台是否都实现了同一组方法（少一个就 `xxx is not a function`）、**三块舞台画布是否各自独立**（共用一块 canvas 会让其中一套形象整块空白）、视频接口是否支持 Range、视频 `readFile` 的路径穿越防护、开屏是否在第一个 `await` 之前就同步播、三个入口是否各自落到对应页、**动作降级链在西湖船娘/Live2D/3D 上是否都有反应**（真实跑一遍，不只看字符串） |

`WebSocket` 说 CDP 协议，**不需要装任何东西**。它验的是**结构性的渲染正确性** ——
采样画布像素而不是检查元素存在性，因为"元素在"和"画出来了"是两件事。

（一块 canvas 只能有一种绘图上下文，于是其中一套整块空白）；
以及 `renderLookPreview` 读西湖船娘没有的字段抛 TypeError，
把整个 `boot()` 打断导致 `initStage()` 没执行、画布停在 300×150 一个像素都没画。

## 数据与隐私

- 所有推理在本机：**Ollama**（对话 / 视觉 / 向量）+ **本机 Qwen TTS**（语音）。
  不调用任何云端 API，不需要任何 API Key。
- 所有持久化都在 `data/` 下：`memory.json`（机体记忆）、`cards.json`（角色卡）、
  `tts-cache/*.wav`（语音缓存）。可直接删除或备份带走。
- 服务默认只监听 `127.0.0.1`；`data/` 目录被静态服务显式屏蔽（403）。

## 已知限制

见 [`docs/评分点对照.md`](docs/评分点对照.md) 第八节「已知的局限」。
简要版：

| 限制 | 说明 |
| --- | --- |
| 非流式接口要整段返回 | `/api/quick-plan` 实测 17.5 s（2 天方案）；页面走流式接口，首字 0.1~1.2 s |
| 舞台动画会和 Ollama 抢算力 | 实测在软件渲染的浏览器里，同一个生成请求会被拖慢数倍；直连接口 15~25 s。演示前可关掉舞台动画 |
| 长天数方案可能写不满 | 7 天方案在 7B 模型上仍可能提前收尾，已由输出质检主动告警 |
| 输出质检是"检查"而非"纠正" | 能发现并标注编造内容，不能阻止模型生成它 |
| 无并发控制 | 多个请求同时打到 Ollama 会互相拖慢，前端已用"生成期间禁用按钮"缓解 |
| 样本库为示例数据 | `.agents/skills/wenlv-assistant/references/` 为公开常识整理，正式使用需替换为本地真实业态数据 |
| 模型需自行获取 | 仓库不含模型文件（第三方版权）。跑一次「获取示例模型.bat」装好示例模型，或把自己的模型放进 `public/models/` |
